# ErdEditorElement

Редактор — это обычный `HTMLElement`, тег `<erd-editor>`, который определяет импорт `@dineug/erd-editor/erd-editor.js`.  
Начиная с версии `5.0.0` импорт корня пакета не определяет ни одного тега. Корень экспортирует `ErdEditorElement` и как тип элемента, и как его класс, а также `defineErdEditor()`, которая определяет тег там, где вы ее вызываете, — см. [Регистрация элементов](./installation.md#registering-the-elements).  
Для страницы, которая лишь показывает диаграмму, [`<erd-viewer>`](./erd-viewer-element.md) — это отдельный элемент только для чтения.

```js
import '@dineug/erd-editor/erd-editor.js';

const editor = document.createElement('erd-editor');
```

Его определение типа приведено ниже.

```ts
interface ErdEditorElement extends HTMLElement {
  readonly: boolean;
  systemDarkMode: boolean; // system dark/light auto
  enableThemeBuilder: boolean;
  enableLocalePicker: boolean;
  enableWelcomeScreen: boolean;
  value: string;
  readonly runtimeValue: string;
  focus: () => void;
  blur: () => void;
  clear: () => void;
  destroy: () => void;
  setInitialValue: (value: string) => void;
  setPresetTheme: (themeOptions: Partial<ThemeOptions>) => void;
  setSystemAppearance: (appearance: 'dark' | 'light' | null) => void;
  setTheme: (theme: Partial<Theme>) => void;
  setLocale: (locale: LocaleOption) => void;
  setSystemLocale: (locale: string | null) => void;
  setKeyBindingMap: (
    keyBindingMap: Partial<
      Omit<
        KeyBindingMap,
        | 'edit'
        | 'stop'
        | 'undo'
        | 'redo'
        | 'zoomIn'
        | 'zoomOut'
        | 'zoomReset'
      >
    >
  ) => void;
  setSchemaSQL: SetSchema;
  setSchemaGraphQL: SetSchema;
  setSchemaDBML: SetSchema;
  setSchemaAML: SetSchema;
  setSchemaJSON: (
    value: string,
    options?: { mode?: 'replace' | 'append' }
  ) => void;
  getSchemaSQL: (
    databaseVendor?: DatabaseVendor,
    options?: SchemaSQLOptions
  ) => string;
  getSharedStore: (
    config?: SharedStoreConfig & {
      mouseTracker?: boolean;
      focusTracker?: boolean;
    }
  ) => SharedStore;
  setDiffValue: (value: string) => void;
}
```

Редактор отрисовывается в закрытом теневом корне, поэтому `editor.shadowRoot` равен `null`, а стили страницы не проникают ни внутрь, ни наружу.  
Ни до чего внутри нельзя добраться селектором — вместо этого задавайте стили через [setTheme](#settheme) и пользовательские свойства `--erd-editor-*`.

Атрибутов всего пять: `readonly`, `system-dark-mode`, `enable-theme-builder`, `enable-locale-picker` и `enable-welcome-screen`, и у всех пяти значение по умолчанию — `false`. Последние два появились в версии `4.0.0`. Каждый из них читает свое значение так, как описано в разделе [readonly](#readonly).

Начиная с версии `4.1.0` на вкладке ERD есть [Обозреватель](../guide/guides/explorer.md) — дерево диаграммы, закрепленное слева от холста, с Поиском и заменой в верхней части. Ни один атрибут, свойство, метод или событие не открывает и не закрывает его и не сообщает о его состоянии: он открывается кнопкой `Explorer` на панели инструментов, пунктом `Toggle Explorer` в быстром поиске или в контекстном меню холста либо привязкой [`findReplace`](#setkeybindingmap).  
Каждый элемент начинает работу с закрытым Обозревателем. То, открыт ли он, а также его ширина, сворачивание и поиск сохраняются, пока существует элемент, — при переключении вкладок и при любой загрузке, включая `setInitialValue`, — и никогда не попадают в `value`, `runtimeValue`, историю изменений или общее хранилище.

Начиная с версии `4.2.0` у таблиц и столбцов наряду с именами могут быть [логические имена](../guide/guides/logical-names.md), а режим отображения имен — настройка документа, как и вкладка, — определяет, что рисует холст: их имена, их логические имена или и то и другое.  
На панели инструментов также есть вкладка [«Словарь»](../guide/guides/dictionary.md) — между `Code Generator` и `Settings`, — которая хранит слова, термины и домены документа, а также лист `Checks`. Это такая же вкладка, как и остальные: ее `canvasType`, `'@dineug/erd-editor/builtin-dictionary'`, удерживается блокировкой `Canvas Type`, поэтому текст, сохраненный на ней, открывается на ней же через [setInitialValue](#setinitialvalue), а переключение на нее записывается в `value` и генерирует [change](#change), только пока эта блокировка выключена. Собственного атрибута, свойства, метода или события, которое открывало бы ее или сообщало о ее состоянии, у нее нет. Ее правки — это изменения документа: они попадают в `value`, генерируют [change](#change) и доходят до соавторов, но их отмена и повтор выполняются по собственной истории изменений каждого листа, а не документа.  
Собственное состояние вкладки — какой лист открыт (сначала это `Domains`), а также поиск, выделение, прокрутка и ширина столбцов каждого листа — сохраняется, пока существует элемент, при переключении вкладок и при любой загрузке, и никогда не попадает в `value`, `runtimeValue`, какую-либо историю изменений или общее хранилище.  
Интерфейс `ErdEditorElement` не получает новых членов. API добавляет поле `logicalNameAsComment` в параметры [getSchemaSQL](#getschemasql), двенадцать [токенов темы](#settheme) и экспорт [dictionaryRowChords](#dictionaryrowchords).

## readonly {#readonly}

Задает возможность редактирования в редакторе.  
Пока он установлен, присваивание `value`, `clear()`, `setSchemaSQL()`, `setSchemaGraphQL()`, `setSchemaDBML()`, `setSchemaAML()`, `setSchemaJSON()`, отмена и повтор — начиная с версии `4.2.0` в том числе на листе вкладки «Словарь» — игнорируются, а событие `change` никогда не генерируется. Вместо этого загружайте документ с помощью [setInitialValue](#setinitialvalue).  
Начиная с версии `5.0.0` редактор только для чтения — это читатель, а не редактор с отключенными элементами управления. Он сохраняет свои шесть вкладок, [Обозреватель](../guide/guides/explorer.md#read-only-editors), мини-карту, быстрый поиск, «Свойства таблицы», [«Просмотр различий»](../guide/guides/table-related-functions.md#diff-viewer), `Export`, режим дзен, а также курсоры, фокус и выделения соавторов, а каждый элемент управления, который изменял бы диаграмму, не рисуется вовсе, а не отображается отключенным. До версии `5.0.0` многие его элементы редактирования все еще отображались, а редактор отбрасывал то, что они отправляли.

На вкладке ERD перетаскивание перемещает холст, где бы оно ни началось, в том числе на таблице, а нажатие ничего не выделяет, не перемещает и не открывает. Указатель, остановившийся на таблице, подсвечивает ее связи; короткий щелчок без движения по таблице или по связи сохраняет эту подсветку, а такой же щелчок в любом другом месте ее гасит, как в [`<erd-viewer>`](./erd-viewer-element.md). Единственное выделение — это контур, который оставляет переход: переход к строке Обозревателя, к одному из его совпадений поиска или к результату быстрого поиска после `#`, `@` или `:` выделяет то, к чему он ведет, а следующий короткий щелчок без движения снимает выделение. Копирование копирует то, что содержит это выделение.  
[Панель инструментов холста](../guide/guides/table-related-functions.md#canvas-toolbar) сохраняет `Zoom out`, уровень масштаба (`Reset zoom`), `Zoom in`, список режимов отображения имен, `Zen Mode` и компас, без `Hand` и `Select`, без `New Table`, `New Memo` и `New Table Group` и без кнопок связей. Меню холста сохраняет `View Option`, `Name View`, `Export` и `Diff Viewer`, меню таблицы сохраняет `Table Properties`, а заметка, связь или группа таблиц не вызывают никакого меню. Быстрый поиск на вкладке ERD не перечисляет ни одной строки, которая записывала бы в диаграмму: он сохраняет `Tab`, `Name View`, `Database`, `Export`, `Toggle Explorer`, строки `Theme` и `Display Language`, которые включают [enableThemeBuilder](#enablethemebuilder) и [enableLocalePicker](#enablelocalepicker), а также поиск по `#`, `@` и `:`. На остальных вкладках он перечисляет то же, что и в редакторе, доступном для редактирования. Панель инструментов показывает название СУБД текстом и не содержит кнопок `Undo`, `Redo` и `Time Travel`.  
Ничто не предлагает `Import`, [`Import and Add`](../guide/guides/file-import-export.md#import-and-add), `Auto Layout`, строку группы таблиц (см. [Группы таблиц](../guide/guides/table-groups.md#read-only-editors)) или [`Map Columns`](../guide/guides/relationship-editing.md#map-columns), и [экран приветствия](#enablewelcomescreen) не показывается.  
Привязки, которые добавляют, удаляют или правят, ничего не делают: `edit`, `addTable`, `addColumn`, `addMemo`, `addTableGroup`, `groupSelectedTables`, `removeTable`, `removeColumn`, `removeSelection`, `primaryKey`, `selectAllTable`, `selectAllColumn`, четыре привязки связей и `handTool`, причем каждая по-прежнему отменяет действие по умолчанию так, как это задает ее параметр. Вставка и `Tab` тоже ничего не делают и доходят до страницы без отмены действия по умолчанию. Привязки масштаба, `zenMode`, `focusView`, `tableProperties` для таблицы, выделенной переходом, `search`, `findReplace`, копирование, `Escape` и клавиши со стрелками продолжают работать. Ни один редактор ячейки, имени заметки или группы таблиц не открывается, и ни одна связь не рисуется.

[Поиск и замена](../guide/guides/find-and-replace.md#read-only-editors) в верхней части Обозревателя только ищет, без стрелки `Toggle Replace` и без строки замены. Панель называется `Explorer`, а всплывающая подсказка кнопки на панели инструментов в любом редакторе — `Explorer (Ctrl + F)` (Windows/Linux) или `Explorer (⌘ + F)` (Mac). Обозреватель открывается в редакторе только для чтения с версии `4.1.0`; в версиях с `3.10.0` по `4.0.0` Поиск и замена открывался там как плавающая панель только для поиска с заголовком `Find`.  
«Свойства таблицы» открываются из меню таблицы или привязкой `tableProperties`, и начиная с версии `3.10.0` в них рядом с заголовком отображается метка `Read only`, а вкладка `Indexes` не позволяет ничего изменить — см. [Свойства таблицы](../guide/guides/table-related-functions.md#table-properties).  
Вкладка «Настройки» несет ту же метку `Read only` и показывает каждую настройку в элементе управления, который не реагирует на нажатие: два переключателя, поле `Maximum comment width` и семь кнопок `Lock` отключены, а строки `Column Order` не перетаскиваются. Скрипты `Before tables` и `After tables` на вкладке «Схема SQL» не принимают ввод. Вкладка [«Визуализация»](../guide/guides/visualization.md) работает так же, как в редакторе, доступном для редактирования, поскольку там ничто не правит документ; шаги `Previous table` и `Next table` в режиме Flow по-прежнему выполняются — их кнопками или клавишами отмены и повтора.  
Вкладка [«Словарь»](../guide/guides/dictionary.md#read-only-editors) по-прежнему открывается: ее листы можно переключать, искать по ним, выделять, прокручивать и копировать из них, а строка листа `Checks` по-прежнему ведет к тому, что она называет. Ни одна ячейка не принимает правку, вставку или очистку, вкладка не показывает ни инструментов `Add Row`, `Delete Rows`, `Import CSV` и `Export CSV`, ни меню сетки, а ее сочетания клавиш для строк ничего не вставляют и не удаляют. Меню таблицы, меню холста и быстрый поиск не предлагают ни [`Derive Physical Names Again`](../guide/guides/dictionary.md#derive-physical-names-again), ни `Derive Physical Name Again`.

Начиная с версии `5.0.0` настройки, которые читатель все еще может менять, остаются на экране этого редактора: прокрутка и масштаб, вкладка, СУБД, язык генератора кода, оба стиля имен, тип кавычек, строки `View Option` и [режим отображения имен](../guide/guides/logical-names.md#read-only-editors) в любом из его списков, который остается на экране с версии `4.2.0`. Какими бы ни были их [блокировки](../guide/guides/settings.md#lock), ни одна из них не доходит до `value`, `runtimeValue`, экспорта `json`, истории отмены, события [change](#change) или общего хранилища, поэтому `value` сохраняет настройки документа, как бы читатель ни смотрел на диаграмму. Панели параметров [Схемы SQL](../guide/guides/schema-sql.md#read-only-editors) и генератора кода подписывают эти настройки `This window only`, пока установлен `readonly`, тогда как в редакторе, доступном для редактирования, подпись — `Saved in the document`. То, что обе вкладки показывают, копируют и сохраняют, следует экрану, как и [getSchemaSQL](#getschemasql), вызванный без указания СУБД.  
До версии `5.0.0` прокрутка, масштаб, переключение вкладки, СУБД и настройки кода читателя попадали в `value`, пока их не удерживала блокировка, чего с СУБД никогда не бывает, а общее хранилище отправляло их остальным редакторам.  
Параметры `This window only` самой вкладки «Схема SQL» — `Statements`, `Header`, начиная с версии `4.2.0` `Write logical names into empty comments` и `Tables` — не сохраняются ни в одном редакторе и по-прежнему действуют, как и окно [`Export image`](../guide/guides/file-import-export.md#image), конструктор темы и окно выбора языка интерфейса. Выбор в конструкторе темы или в окне выбора языка интерфейса по-прежнему генерирует [changePresetTheme](#changepresettheme) или [changeLocale](#changelocale).

Пока он установлен, ничто не попадает в историю отмены, включая прокрутку и изменение масштаба, а [общее хранилище](#getsharedstore) редактора не отправляет изменений: только то, что отправляют его трекеры о курсоре, фокусе, выделении и рамке перетаскивания читателя, и регистры, которые запрашивает другой редактор при присоединении (см. [Совместное редактирование](./advanced/collaborative-editing.md)). Он по-прежнему применяет все изменения, которые присылают остальные. Изменение СУБД, настройки генератора кода или строки `View Option` доходит до документа, а до экрана — тоже, если только читатель не менял эту настройку именно там, и общее переключение режима отображения имен в любом случае отображается на экране.

Его включение завершает все, что было открыто: редактор ячейки, имени заметки или группы таблиц, рисуемую связь, перетаскивание таблицы, заметки, группы таблиц или столбца, копии при перетаскивании с `Alt`, изменение размера заметки или группы таблиц, предварительный просмотр или размещение `Auto Layout`, еще выполняющиеся, `Map Columns`, Time Travel и палитру цветов. Он снимает выделение, откладывает инструмент «Рука» и сначала отправляет то, что каждое общее хранилище еще удерживает от перетаскивания или прокрутки, как это делает [flushStreamBuffers](./advanced/collaborative-editing.md#flushstreambuffers). «Свойства таблицы», теперь только для чтения, «Просмотр различий» и окно `Export image` остаются открытыми, а прокрутка, масштаб, вкладка и режим отображения имен остаются прежними. Элемент, который при первом монтировании уже находится в режиме только для чтения, начинает так же, а элемент, который хост переносит по странице, сохраняет контур, оставленный переходом.  
Его выключение возвращает элементы управления редактированием, ничего не выделяя и не открывая. СУБД, язык генератора кода, оба стиля имен, тип кавычек и строки `View Option` возвращаются к значениям документа, а прокрутка, масштаб, вкладка и режим отображения имен остаются там, где их оставил читатель, и `value` сохраняет значения документа, пока читатель не изменит их снова. Ни то, ни другое переключение не генерирует `change`.  
Атрибут без значения, `=""` и `="true"` читаются как `true`. `="false"` читается как `false`, и так же читается любая другая строка — включая принятую в HTML запись `readonly="readonly"`.

```js
editor.readonly = true;
// or
editor.setAttribute('readonly', 'true');
```

```html
<erd-editor readonly></erd-editor>
```

## systemDarkMode {#systemdarkmode}

Определяет, синхронизироваться ли автоматически с темным или светлым режимом системы.  
Начиная с версии `4.0.0` его включение устанавливает `appearance` темы в `'system'`, как и `setPresetTheme({ appearance: 'system' })`. После этого редактор показывает светлое или темное оформление, о котором сообщает операционная система или которое задает [setSystemAppearance](#setsystemappearance), и переключается при его изменении.  
Последующий вызов [setPresetTheme](#setpresettheme) со значением `'light'` или `'dark'` либо выбор `Light` или `Dark` в конструкторе темы или в быстром поиске заменяет `'system'` и сохраняется: следующее изменение в ОС его больше не перезаписывает, хотя `systemDarkMode` по-прежнему равен `true`. До версии `4.0.0` следующее изменение в ОС его перезаписывало.  
Если выключить его, пока оформление равно `'system'`, сохраняется светлое или темное оформление, показанное в этот момент. Если выключить его после того, как оформление было изменено с `'system'` на другое, оформление остается как есть.  
Его изменение не генерирует никаких событий.

```js
editor.systemDarkMode = true;
// or
editor.setAttribute('system-dark-mode', 'true');
```

```html
<erd-editor system-dark-mode></erd-editor>
```

## enableThemeBuilder {#enablethemebuilder}

Определяет, доступен ли интерфейс для удобной настройки предустановленных тем.  
Он показывает кнопку `Theme` на панели инструментов, которая открывает конструктор темы с параметрами `Accent color`, `Gray color` и `Appearance`. Начиная с версии `4.0.0` параметр `Appearance` предлагает `System` наряду с `Light` и `Dark`, а пока этот атрибут включен, быстрый поиск показывает `Theme` с вариантами `System`, `Light` и `Dark`. См. [Язык и тема](../guide/guides/language-and-theme.md).

![Открытие конструктора темы с панели инструментов, выбор цвета акцента и оттенка серого и переключение оформления на Light, а затем на System](/img/demo-theme-builder.webp)

```js
editor.enableThemeBuilder = true;
// or
editor.setAttribute('enable-theme-builder', 'true');
```

```html
<erd-editor enable-theme-builder></erd-editor>
```

Изменение предустановленной темы на этой панели или в быстром поиске генерирует событие [changePresetTheme](#changepresettheme).

## enableLocalePicker {#enablelocalepicker}

Начиная с версии `4.0.0` определяет, доступен ли в редакторе выбор языка интерфейса.  
Он показывает кнопку `Display Language` на панели инструментов — после `Theme`, когда показаны обе. Кнопка открывает окно выбора языка интерфейса, а быстрый поиск показывает `Display Language`. И там, и там доступны `System` и 25 языков — см. [Язык и тема](../guide/guides/language-and-theme.md).  
Он также определяет, что показывает редактор, пока не вызван [setLocale](#setlocale) и не выбран язык: `'system'`, пока он включен, и английский, пока он выключен, поэтому элемент, в котором ничего не настроено, остается на английском, как и всегда. Включение или выключение сразу переключает между этими двумя вариантами. Если язык уже задан или выбран, этот выбор сохраняется независимо от того, включен атрибут или выключен.  
Установите его до добавления элемента на страницу, чтобы уже первый кадр следовал `'system'`.  
Выбор языка генерирует [changeLocale](#changelocale).

```js
editor.enableLocalePicker = true;
// or
editor.setAttribute('enable-locale-picker', 'true');
```

```html
<erd-editor enable-locale-picker></erd-editor>
```

## enableWelcomeScreen {#enablewelcomescreen}

Начиная с версии `4.0.0` определяет, встречает ли пустая диаграмма пользователя [экраном приветствия](../guide/guides/editing-start.md#welcome-screen).  
Он отображается поверх вкладки ERD, пока в документе нет ни одной таблицы, ни одной показанной заметки и ни одной показанной группы таблиц. Он не показывается, пока установлен атрибут `readonly`, в режиме дзен, а также пока открыто окно «Свойства таблицы», просмотр различий, путешествие во времени или предварительный просмотр Автоматического размещения. Первая таблица, показанная заметка или показанная группа таблиц убирает его, а отмена, возвращающая к пустой диаграмме, показывает его снова.  
Его строки `New Table`, `New Memo` и `Command Palette` показывают первое сочетание клавиш привязок `addTable`, `addMemo` и `search` в том виде, в каком их оставил [setKeyBindingMap](#setkeybindingmap), а для привязки, оставленной пустой, не показывают ничего. Его стрелки указывают на кнопки `Theme` и `Display Language` только там, где их показывают `enableThemeBuilder` и `enableLocalePicker`.  
В его меню `↑`, `↓`, `Home` и `End` перемещают между строками, и для них отменяется действие по умолчанию и останавливается распространение. Для `Enter` и `Space` распространение останавливается, но действие по умолчанию не отменяется, поэтому их получает строка в фокусе, а `Escape` в списке форматов `Import` возвращает назад, с отменой действия по умолчанию и остановкой распространения. Все остальные клавиши, как обычно, доходят до редактора и страницы.  
Он ничего не меняет в документе, поэтому оставляет `value` без изменений и не генерирует `change`.  
Включайте его после того, как [setInitialValue](#setinitialvalue) загрузил документ, как это делают официальные хосты, чтобы экран никогда не мелькал поверх файла, который еще загружается.

```js
editor.enableWelcomeScreen = true;
// or
editor.setAttribute('enable-welcome-screen', 'true');
```

```html
<erd-editor enable-welcome-screen></erd-editor>
```

## value {#value}

### getter {#getter}

Возвращает текущий документ в виде строки JSON по [схеме](./advanced/schema.md), которую определяет редактор.  
Начиная с версии `4.0.0` это форма хранения — документ в том виде, в каком его хранит файл; ее же записывает экспорт `json` и сохраняют официальные хосты. Она содержит только действующие сущности, без удаленных, без порядка наложения и без того, что редактор вычисляет сам, например измеренной ширины, меток ключей и точек привязки связей. Ключи сущностей идут в фиксированном порядке, отступ составляет два пробела, а в конце стоит перевод строки, поэтому один и тот же документ всегда дает одни и те же байты.  
Начиная с версии `4.2.0` он также опускает то, что пусто: пустой список в `doc`, пустую коллекцию, строку словаря, которая ничего не содержит, и пустое текстовое поле сущности, например имя, комментарий, тип данных, значение по умолчанию или цвет. Список внутри сущности, например `columnIds` таблицы, записывается и пустым. В новом документе `doc` равен `{}`, а `collections` в нем нет, поэтому считайте отсутствующее поле, список или коллекцию пустыми. Он содержит логические имена и флаги сформированных имен таблиц и столбцов, привязки столбцов к доменам, а также слова, термины и домены, причем каждый словарь записывается как одна строка заголовков с именами полей, за которой следуют его строки, по одной на строку текста, в порядке строк на листе. См. [Форма хранения и значение времени выполнения](./advanced/schema.md#storage-form-and-runtime-value).  
Каждая настройка с включенной [блокировкой](../guide/guides/settings.md#lock) записывается с заблокированным значением, а не так, как ее показывает экран. Блокировка `Viewport` удерживает `originX`, `originY` и `zoomLevel`, а `Canvas Type`, `Language`, `Table Name Case`, `Column Name Case`, `Bracket Type` и начиная с версии `4.2.0` `Name View` удерживают каждая свою настройку. Режим отображения имен записывается как `nameViewMode`, и только пока он не равен `'physical'`. Все остальные настройки записываются как есть, а `lockSettings` записывается всегда. О битах см. [Settings](./advanced/schema.md#settings); бит блокировки `Name View` читается наоборот.  
Начиная с версии `5.0.0` настройки, которые меняет читатель редактора [только для чтения](#readonly), записываются со значениями документа тоже, заблокированы они или нет, поскольку остаются на его экране.  
В новом документе включены все блокировки — будь то документ, который элемент показывает до получения значения, или документ, загруженный из пустого значения. Его `value` сохраняет начало координат `0, 0`, масштаб `1`, вкладку ERD, язык Генератора кода, стили имен и тип кавычек по умолчанию, а начиная с версии `4.2.0` и режим `Physical Names`, пока не выключена соответствующая блокировка.  
До версии `4.0.0` он возвращал весь документ в том виде, в каком его хранил редактор, с учетом `ignoreSaveSettings`. Документ в том виде, в каком его хранит редактор, теперь возвращает [runtimeValue](#runtimevalue), а `ignoreSaveSettings` больше не читается и не записывается.

```js
const data = editor.value;
```

### setter {#setter}

Загружает ранее сохраненное состояние редактора. Он заменяет весь документ — текущий сначала очищается. Начиная с версии `4.2.0` это относится и к словам, терминам и доменам: документ получает те, что содержит текст, или не получает никаких, а собственная история изменений каждого листа вкладки «Словарь» очищается.  
Как и `clear()`, `setInitialValue()` и методы `setSchema*` в режиме по умолчанию `mode: 'replace'`, он также сбрасывает вид Flow на вкладке «Визуализация»: его размещение, таблицы, до которых он сужен, отображение строк, масштаб и перемещение, а начиная с версии `4.2.0` и таблицы, по которым делают шаги его кнопки `Previous table` и `Next table`. Добавление (`mode: 'append'`) его не сбрасывает.  
Он записывается в историю изменений, что позволяет выполнить `Undo, Redo`, и генерирует `change`.  
Он принимает форму хранения, [runtimeValue](#runtimevalue) или файл, сохраненный более ранней версией.  
Пустая строка или любое значение, не являющееся строкой, загружает новый документ, а не вызывает ошибку, поэтому проверяйте значение перед присваиванием.  
Это тот же новый документ, который создает `setInitialValue('')`: пустой, с настройками по умолчанию и начиная с версии `4.0.0` со всеми включенными блокировками. В версиях `3.10.x` он не сохранял ни положение прокрутки, ни масштаб, а до них сохранял и то и другое.  
Общее хранилище передает эту загрузку соавторам вместе с полным JSON нового документа, поэтому каждый участник, включая участников с более старой версией, загружает его, хотя редактор до версии `4.2.0` отбрасывает то, чего не знает, например логические имена, привязки к доменам и словари, — см. [Разные версии в одном сеансе](./advanced/collaborative-editing.md#mixing-releases).  
Начиная с версии `4.0.0` блокировки загруженного документа и заблокированные значения, которые затем записывает `value`, берутся из текста, а вид оказывается там, где его располагает текст, либо на диаграмме, если в этом месте не отрисована ни одна ее часть. Для каждой из остальных настроек, которые блокирует текст, — вкладки, языка Генератора кода, стилей имен, типа кавычек и начиная с версии `4.2.0` режима отображения имен — редактор продолжает показывать то же, что показывал до загрузки. Настройка, которую текст оставляет незаблокированной, принимает значение из текста. В файле, сохраненном до версии `4.2.0`, блокировка `Name View` не указана, если только редактор версии `4.2.0` не выключил в нем эту блокировку, поэтому такой файл загружается с режимом отображения имен, заблокированным на `Physical Names`, а редактор сохраняет режим отображения имен, который показывал. [setInitialValue](#setinitialvalue), напротив, принимает все значения из текста; о тексте, в котором не указаны блокировки, см. также там.  
Текст, не являющийся JSON, например файл с оставшимися маркерами конфликта слияния, тоже не вызывает ошибку: документ очищается, его настройки остаются прежними, а ошибка разбора выводится в консоль.  
Пока установлен атрибут `readonly`, присваивание игнорируется; чтобы загрузить документ в редактор только для чтения, используйте [setInitialValue](#setinitialvalue).

```js
editor.value = 'json...';
```

## runtimeValue {#runtimevalue}

Начиная с версии `4.0.0` возвращает документ в том виде, в каком его хранит этот редактор, в виде строки JSON. У него нет сеттера, поэтому присваивание в коде в строгом режиме выбрасывает исключение.  
Оно содержит то, что опускает [value](#value): удаленные сущности и их порядок, порядок наложения, измеренную ширину, метки ключей, точки привязки связей и последовательности, а начиная с версии `4.2.0` — пустые текстовые поля, списки в `doc` и коллекции; строки, удаленные с листа вкладки «Словарь», и строки, которые ничего не содержат; ключ порядка каждой строки словаря; списки слов, терминов и доменов в `doc`; и привязку к удаленному домену. Заблокированные настройки и здесь записываются с заблокированными значениями.  
Используйте его, чтобы через [setInitialValue](#setinitialvalue) инициализировать другой редактор, который подключается к уже идущему сеансу, например редактор соавтора или второй вид того же документа. В этом случае отмена удаления, которую сеанс отправит позже, восстановит там сущность целиком, тогда как редактор, инициализированный из `value`, не содержит удаленных сущностей и вместо этого восстановит пустую безымянную таблицу, а начиная с версии `4.2.0` — пустую строку словаря. См. [Совместное редактирование](./advanced/collaborative-editing.md).  
Сборщик мусора больше не убирает удаленные сущности, поэтому они остаются в нем до следующего открытия документа из файла.  
Никогда не записывайте его в файл: сохраняйте `value`, который принимает [JSON Schema](./advanced/schema.md#json-schema), в отличие от этого значения.

```js
otherEditor.setInitialValue(editor.runtimeValue);
```

## setInitialValue {#setinitialvalue}

Загружает ранее сохраненное состояние редактора. Сама загрузка не записывается в историю изменений, поэтому ее нельзя отменить, и событие `change` не генерируется.  
Он также очищает историю изменений, поэтому ничего из сделанного до загрузки нельзя отменить или повторить в загруженном документе, а начиная с версии `4.2.0` — и собственную историю изменений каждого листа вкладки «Словарь».  
Он принимает форму хранения, [runtimeValue](#runtimevalue) или файл, сохраненный более ранней версией, и, в отличие от присваивания `value`, принимает все настройки из текста, включая вкладку и настройки кода.  
Пустая строка или любое значение, не являющееся строкой, загружает новый документ, а не вызывает ошибку, поэтому `setInitialValue('')` создает пустую диаграмму.  
Начиная с версии `4.0.0` в этом новом документе, который элемент также показывает до получения какого-либо значения, включены все блокировки. Прокрутка, масштабирование, переключение вкладок и изменение языка Генератора кода, стилей имен, типа кавычек или начиная с версии `4.2.0` режима отображения имен оставляют `value` без изменений и не генерируют `change`. В версиях `3.10.x` он не сохранял ни положение прокрутки, ни масштаб, а до них сохранял и то и другое.  
Документ, загруженный из текста, сохраняет указанные в нем блокировки. Документ, в котором блокировки не указаны, — любой файл, сохраненный до версии `4.0.0`, независимо от значения его `ignoreSaveSettings`, и файл `.vuerd` v2 — открывается со всеми включенными блокировками, с `Viewport`, заблокированным в начале координат `0, 0` и с масштабом `1`, на вкладке ERD, а язык, стили имен и тип кавычек остаются такими, какими он их сохранил.  
Начиная с версии `4.2.0` текст, в котором указаны блокировки, но не указана блокировка `Name View`, тоже открывается с этой блокировкой включенной, даже если все остальные блокировки выключены. Файл, сохраненный до версии `4.2.0`, является таким текстом, если только редактор версии `4.2.0` не выключил в нем эту блокировку (см. [Settings](./advanced/schema.md#settings)). Он открывается в режиме `Physical Names`, как и текст, в котором не указано ни одной блокировки.  
В обоих случаях вид открывается в положении вида документа — сохраненном в тексте, если в нем указаны блокировки, или в начале координат `0, 0` с масштабом `1`, если они не указаны, — либо на диаграмме, если в этом месте не отрисована ни одна ее часть. Заблокированный `Viewport` по-прежнему сохраняет свои заблокированные значения в `value`.  
Начиная с версии `4.0.0` он также сбрасывает состояние совместной работы прежнего документа, а уже подписанное [общее хранилище](#getsharedstore) этого редактора снова запрашивает состояние у других редакторов, поэтому редактор, перезагруженный в идущем сеансе, догоняет остальных. Инициализируйте такой редактор значением [runtimeValue](#runtimevalue) другого редактора.  
Текст, не являющийся JSON, тоже не вызывает ошибку: документ очищается, его настройки остаются прежними, а ошибка разбора выводится в консоль.  
В отличие от присваивания `value`, его не блокирует атрибут `readonly`, поэтому именно так документ загружается в редактор только для чтения. Затем редактор только для чтения показывает настройки загруженного текста, отбрасывая те, которые его читатель изменил на экране.

```js
editor.setInitialValue('json...');
```

Загрузка при запуске, сохранение при изменении.

```js
editor.setInitialValue(localStorage.getItem('my-diagram') ?? '');
editor.addEventListener('change', () => {
  localStorage.setItem('my-diagram', editor.value);
});
```

## События {#event}

Публичных событий всего три: `change`, `changePresetTheme` и `changeLocale`; событие `changeLocale` появилось в версии `4.0.0`.  
Элемент также отправляет сам себе внутренние события `@dineug/erd-editor/internal-*` для собственной внутренней работы; они не входят в API.

### change {#change}

При изменениях в редакторе генерируется событие.  
Событие генерируется с задержкой (debounce) 200 мс и не генерируется, пока `readonly` равен `true`.  
Оно возникает при любом изменении документа — правке в интерфейсе, присваивании `value`, `clear()`, вызове каждого из методов `setSchema*`, а начиная с версии `4.0.0` и при `setSchemaJSON()` и `Import and Add`. `setInitialValue` его не генерирует.  
Начиная с версии `4.2.0` сюда входят каждая правка на вкладке [«Словарь»](../guide/guides/dictionary.md) и каждая отмена или повтор такой правки, изменение логического имени или привязки к домену, команда `Derive Physical Names Again` и переключение режима отображения имен, пока блокировка `Name View` выключена.  
Ничто из сделанного в режиме Flow на вкладке «Визуализация» его не генерирует — ни масштабирование, ни перемещение вида, ни перемещение карточек, ни `Tidy Up`, ни отображение строк, ни сужение вида с карточки, ни начиная с версии `4.2.0` шаги кнопками `Previous table` и `Next table` или клавишами отмены и повтора, — поскольку ничто из этого не является изменением документа. Исключение — его список `Name View`: переключение в нем генерирует событие, пока блокировка `Name View` выключена, как и переключение на вкладке ERD.  
Начиная с версии `4.0.0` его не генерирует и изменение настройки с включенной [блокировкой](../guide/guides/settings.md#lock), потому что оно затрагивает только экран и никогда не затрагивает `value`: прокрутка или масштабирование холста ERD, пока заблокирован `Viewport`, переключение вкладки, пока заблокирован `Canvas Type`, изменение языка Генератора кода, стиля имен таблиц, стиля имен столбцов или типа кавычек, пока включена собственная блокировка этой настройки, и начиная с версии `4.2.0` переключение режима отображения имен, пока заблокирован `Name View`. Не учитываются только эти изменения, поэтому пакет изменений, который также правит документ, все равно его генерирует. Блокировка или разблокировка настройки его генерирует.  
В новом документе и в любом файле, сохраненном до версии `4.0.0`, включены все блокировки, а в любом файле, сохраненном до версии `4.2.0`, включена блокировка `Name View`, если только редактор версии `4.2.0` не выключил ее в этом файле, поэтому по умолчанию прокрутка, масштабирование, переключение вкладок и переключение режима отображения имен ничего не генерируют. Это относится к фокусу на таблицах с вкладки ERD, к кнопке карточки со значком внешней ссылки, которая возвращает из режима Flow на вкладку ERD, к переходу к строке Обозревателя или к совпадению поиска, к открытию Обозревателя или переходу к результату быстрого поиска с другой вкладки, а начиная с версии `4.2.0` и к переходу к таблице или столбцу из строки листа `Checks` вкладки «Словарь». Каждое из этих действий генерирует одно событие `change`, только пока выключена охватывающая его блокировка: `Canvas Type` — для переключения вкладки и `Viewport` — для прокрутки, которую также выполняют кнопка карточки, результат быстрого поиска, строка Обозревателя, совпадение поиска или строка листа `Checks`. Начиная с версии `4.1.0` каждая из этих прокруток подчиняется одному правилу — [Куда ведет переход](../guide/guides/table-related-functions.md#where-a-jump-lands), — поэтому результат быстрого поиска для таблицы больше не вызывает прокрутку каждый раз, а переход, при котором правило оставляет вид на месте, не создает прокрутки, которая могла бы сгенерировать событие. Открытие, закрытие или изменение ширины Обозревателя сужает или расширяет холст, не сдвигая его начало координат, и тоже ничего не генерирует. До версии `4.0.0` прокрутка, масштабирование и переключение вкладок всегда его генерировали, даже если `editor.value` оставался прежним.  
Чтобы пропускать записи, которые ничего не меняют, сравнивайте `editor.value` со значением, которое вы сохранили последним, а не с загруженным файлом: файл, записанный более ранней версией, файл v2 или файл, отредактированный вручную, может дать в `value` другой результат сразу после загрузки, потому что `value` записывает его в форме хранения. То же может произойти с файлом, у которого блокировка `Viewport` выключена, а начало координат на этом экране не показывает ни одной части диаграммы: загрузка перемещает вид на диаграмму, и `value` записывает то место, где он оказался. Начиная с версии `4.0.0` измеренная ширина больше к этому не приводит, потому что `value` ее не содержит. Начиная с версии `4.2.0` другой результат может дать и файл, сохраненный версией `4.0.0` или `4.1.0`, так как `value` теперь опускает его пустые текстовые поля, списки и коллекции, поэтому такой файл перезаписывается один раз — при следующем сохранении. Хост, который записывает файлы, может вместо этого отличать правку от изменения вида с помощью `changed` хранилища репликации — см. [on@change](./advanced/remote-storage.md#onchange).  
Событие не содержит `detail`, не всплывает и не пересекает границу теневого корня, поэтому подписывайтесь на сам элемент и читайте `editor.value` в обработчике.

```js
editor.addEventListener('change', event => {
  const data = event.target.value;
});
```

### changePresetTheme {#changepresettheme}

Возникает, когда предустановленная тема изменяется во встроенном конструкторе темы или начиная с версии `4.0.0` через `Theme` в быстром поиске. Его генерирует каждый выбор, в том числе выбор уже действующего варианта.  
Программный вызов [setPresetTheme](#setpresettheme) или [setSystemAppearance](#setsystemappearance), а также включение или выключение [systemDarkMode](#systemdarkmode) его не генерируют.  
`event.detail` содержит полный объект `ThemeOptions` после выбора — `{ appearance, grayColor, accentColor }`, — а не запрошенный частичный объект. Начиная с версии `4.0.0` его `appearance` равен `'system'`, пока выбран `System`, а не показываемому светлому или темному оформлению, поэтому сохраняйте его как есть и передавайте обратно в `setPresetTheme`.

```js
editor.addEventListener('changePresetTheme', event => {
  const themeOptions = event.detail;
});
```

### changeLocale {#changelocale}

Начиная с версии `4.0.0` возникает, когда язык выбирается в редакторе — в окне выбора языка интерфейса или через `Display Language` в быстром поиске; оба способа включает [enableLocalePicker](#enablelocalepicker).  
Оно возникает после применения языка, при каждом выборе, в том числе при выборе уже действующего варианта. [setLocale](#setlocale) и [setSystemLocale](#setsystemlocale) никогда его не генерируют, как и изменение языков браузера. Смена языка не генерирует `change`.  
`event.detail` — это `{ locale }`, значение типа `LocaleOption`: `'system'`, если выбран `System`, иначе код языка. Элемент не запоминает выбор, поэтому сохраните его и передайте в `setLocale` при следующей загрузке.  
Как и `change`, оно не всплывает, поэтому подписывайтесь на сам элемент.

```js
editor.addEventListener('changeLocale', event => {
  const { locale } = event.detail; // 'system' | 'ko-KR' | ...
});
```

## clear {#clear}

Очищает документ, удаляя все таблицы, столбцы, связи, индексы и заметки, начиная с версии `4.0.0` — все группы таблиц, а начиная с версии `4.2.0` — слова, термины и домены вкладки «Словарь», очищая также собственную историю изменений каждого листа.  
Все настройки сохраняются, включая базу данных, положение вида, масштаб, параметры вида таблиц, каждую блокировку с ее значением и скрипты `Before tables` и `After tables` на вкладке «Схема SQL», поэтому очищенный файл продолжает сохранять то же, что и раньше. Чтобы вместо этого начать новый документ, присвойте `''` свойству `value` или вызовите `setInitialValue('')`.  
Он записывается в историю изменений, поэтому его можно отменить, и генерирует `change`. Отмена возвращает документ в том виде, в каком его хранил редактор, включая его слова, термины и домены, причем каждая заблокированная настройка получает свое заблокированное значение. Пока установлен атрибут `readonly`, он игнорируется.

```js
editor.clear();
```

## destroy {#destroy}

Полностью уничтожает экземпляр редактора, после чего его нельзя использовать повторно.  
Он освобождает обработчики и подписки редактора и уничтожает все общие хранилища, возвращенные [getSharedStore](#getsharedstore).  
Пакет потока, который общее хранилище еще удерживает, отбрасывается вместе с ним; чтобы отправить его, сначала вызовите [flushStreamBuffers](./advanced/collaborative-editing.md#flushstreambuffers) этого хранилища.

```js
editor.destroy();
```

## setKeyBindingMap {#setkeybindingmap}

Переопределяет сочетания клавиш.  
`edit`, `stop`, `undo`, `redo`, `zoomIn`, `zoomOut` и `zoomReset` фиксированы, и их нельзя переопределить.  
Учитывается только двадцать одно имя из списка ниже; все остальное в объекте игнорируется, в том числе фиксированные имена.  
Начиная с версии `3.10.0` привязку `search` можно переопределить, и появилась привязка `findReplace`. Раньше привязка `search` была фиксированной. В версии `4.0.0` появилась привязка `removeSelection`. В версии `4.1.0` появились `addTableGroup` и `groupSelectedTables`.  
Значение привязки должно быть массивом `ShortcutOption[]`. Строка сама по себе игнорируется, поэтому пишите `{ addTable: [{ shortcut: 'Alt+KeyN' }] }`, а не `{ addTable: 'Alt+KeyN' }`.  
Пустой массив допускается и ничего не привязывает: `setKeyBindingMap({ findReplace: [] })` оставляет `Ctrl + F` (Windows/Linux) или `⌘ + F` (Mac) странице, а `{ search: [] }` делает то же для `Ctrl + K` (Windows/Linux) или `⌘ + K` (Mac). Кнопка `Search` на панели инструментов по-прежнему открывает быстрый поиск, кнопка `Explorer` на панели инструментов по-прежнему открывает и закрывает Обозреватель, а пункт `Toggle Explorer` в быстром поиске и в контекстном меню холста по-прежнему открывает Обозреватель с поиском или закрывает его; ни один из них не показывает сочетание клавиш для имени, оставленного пустым. `{ removeSelection: [] }` оставляет `Delete` и `Backspace` странице, и тогда пункты удаления в меню таблицы, заметки и группы таблиц (`Delete`, `Delete selected`, `Delete column`, `Delete columns`) не показывают сочетание клавиш.  
Начиная с версии `4.1.0` значение `{ addTableGroup: [] }` оставляет странице `Alt + G` (Windows/Linux) или `⌥ + G` (Mac), а `{ groupSelectedTables: [] }` — `T`, затем `G`. `New Table Group` на панели инструментов холста, в контекстном меню холста и в быстром поиске, `Group selected tables` в меню таблицы и `Group Selected Tables` в быстром поиске по-прежнему работают, но сочетание клавиш не показывается. Всплывающие подсказки кнопок `New Table`, `New Memo` и `New Table Group` на панели инструментов холста называют первое сочетание клавиш привязок `addTable`, `addMemo` и `addTableGroup`, а для привязки, оставленной пустой, — только саму кнопку.  
Начиная с версии `4.2.0` привязки `addColumn` и `removeColumn` также задают сочетания клавиш для строк в сетке вкладки «Словарь», как описано ниже, поэтому переназначение любой из них переносит и эти сочетания. Значение `{ addColumn: [] }` не оставляет сетке сочетания для вставки строк, и тогда два пункта вставки в меню сетки не показывают сочетание клавиш; `{ removeColumn: [] }` не оставляет ей сочетания для их удаления, и тогда пункт удаления в меню и всплывающая подсказка `Delete Rows` тоже не показывают сочетание.  
Вызов выполняет частичное слияние: имена, которые вы не указали, сохраняют значения по умолчанию, а повторный вызов сохраняет предыдущие изменения. Геттера для текущих привязок нет: [createKeyBindingMap](#createkeybindingmap) возвращает значения по умолчанию, а не то, что изменил `setKeyBindingMap`.

```ts
type ShortcutOption = {
  shortcut: string;
  preventDefault?: boolean;
  stopPropagation?: boolean;
};

const defaultKeyBindingMap: Omit<
  KeyBindingMap,
  | 'edit'
  | 'stop'
  | 'undo'
  | 'redo'
  | 'zoomIn'
  | 'zoomOut'
  | 'zoomReset'
> = {
  search: [
    { shortcut: '$mod+KeyK', preventDefault: true, stopPropagation: true },
  ],
  findReplace: [
    { shortcut: '$mod+KeyF', preventDefault: true, stopPropagation: true },
  ],
  addTable: [{ shortcut: 'Alt+KeyN', preventDefault: true }],
  addColumn: [{ shortcut: 'Alt+Enter', preventDefault: true }],
  addMemo: [{ shortcut: 'Alt+KeyM', preventDefault: true }],
  addTableGroup: [
    { shortcut: 'Alt+KeyG', preventDefault: true, stopPropagation: true },
  ],
  groupSelectedTables: [{ shortcut: 'KeyT KeyG', preventDefault: true }],
  removeTable: [
    { shortcut: '$mod+Backspace', preventDefault: true },
    { shortcut: '$mod+Delete', preventDefault: true },
  ],
  removeColumn: [
    { shortcut: 'Alt+Backspace', preventDefault: true },
    { shortcut: 'Alt+Delete', preventDefault: true },
  ],
  removeSelection: [
    { shortcut: 'Delete', preventDefault: true },
    { shortcut: 'Backspace', preventDefault: true },
  ],
  primaryKey: [{ shortcut: 'Alt+KeyK', preventDefault: true }],
  selectAllTable: [
    { shortcut: '$mod+KeyA', preventDefault: true },
    { shortcut: '$mod+Alt+KeyA', preventDefault: true },
  ],
  selectAllColumn: [{ shortcut: 'Alt+KeyA', preventDefault: true }],
  relationshipZeroOne: [{ shortcut: '$mod+Alt+Digit1', preventDefault: true }],
  relationshipZeroN: [{ shortcut: '$mod+Alt+Digit2', preventDefault: true }],
  relationshipOneOnly: [{ shortcut: '$mod+Alt+Digit3', preventDefault: true }],
  relationshipOneN: [{ shortcut: '$mod+Alt+Digit4', preventDefault: true }],
  tableProperties: [{ shortcut: 'Alt+Space', preventDefault: true }],
  focusView: [
    { shortcut: 'Alt+KeyF', preventDefault: true, stopPropagation: true },
  ],
  handTool: [{ shortcut: 'Space', preventDefault: true }],
  zenMode: [
    { shortcut: 'Alt+KeyZ', preventDefault: true, stopPropagation: true },
  ],
};

// example
editor.setKeyBindingMap({
  addTable: [{ shortcut: '$mod+KeyN', preventDefault: true }],
});
```

`selectAllTable`, `handTool`, `removeSelection` и начиная с версии `4.1.0` `groupSelectedTables` уступают курсору ввода: пока фокус находится в поле ввода, многострочном поле или элементе `contenteditable`, `$mod + A` выделяет текст, `Space` вводит пробел, `Delete` и `Backspace` стирают текст, а `T`, затем `G` вводит эти две буквы, вместо того чтобы действовать на холсте. Ни для одного из этих нажатий действие по умолчанию не отменяется. Любые сочетания, на которые вы их переназначите, ведут себя так же.

Начиная с версии `4.0.0` привязка `removeSelection` (`Delete` или `Backspace`) удаляет выделение на вкладке ERD одним шагом отмены, без подтверждения. Если выделена только таблица в фокусе, выделен один или несколько ее столбцов и при текущем масштабе ее строки отрисовываются, привязка удаляет эти столбцы; в противном случае она удаляет все выделенные таблицы, заметки и группы таблиц, сохраняя таблицы групп. См. [Удаление таблиц и заметок](../guide/guides/table-related-functions.md#table-and-memo-deletion).  
Удерживаемая клавиша удаляет один раз, и ничего не удаляется, пока открыто поле редактирования ячейки, заметки или имени группы таблиц. Вне текстового поля и панелей и вкладок, которые удерживают привязки (см. [createKeyBindingMap](#createkeybindingmap)), действие по умолчанию для нажатия отменяется на любой вкладке, пока редактор в фокусе, в том числе на кнопке панели инструментов в фокусе, а также в редакторе только для чтения, где ничего не удаляется.

Начиная с версии `4.1.0` привязка `addTableGroup` (`Alt+KeyG`) активирует на вкладке ERD рисование группы `New Table Group`: следующее нажатие основной кнопки мыши на холсте рисует группу, а повторное нажатие сочетания отменяет рисование, как и кнопка `New Table Group` на панели инструментов холста. Привязка `groupSelectedTables` (`KeyT KeyG`, `T`, затем `G`) помещает выделенные таблицы в новую группу и открывает поле редактирования ее имени, как и пункт `Group selected tables` в контекстном меню таблицы. Если ни одна таблица не выделена, она ничего не добавляет; выделенная заметка или группа таблиц не учитывается. См. [Рисование группы](../guide/guides/table-groups.md#drawing-a-group) и [Группировка выделенных таблиц](../guide/guides/table-groups.md#grouping-selected-tables).  
Обе действуют только там, где меню предлагают группу: они не действуют, пока установлен атрибут `readonly`, пока параметр вида `Table Groups` скрывает группы или пока открыто поле редактирования ячейки, заметки или имени группы таблиц. Как и другие привязки холста, они действуют только на вкладке ERD и не действуют, пока открыт быстрый поиск, окно «Свойства таблицы», просмотр различий, путешествие во времени, предварительный просмотр Автоматического размещения, `Export image` или `Map Columns`. Там, где они ничего не делают, действие по умолчанию для нажатия все равно отменяется, если только `groupSelectedTables` не уступает курсору ввода. Для `addTableGroup` также останавливается распространение, как и для `focusView` и `zenMode`, поэтому обработчик `keydown` на странице в фазе всплытия его никогда не получает.

Начиная с версии `4.2.0` на вкладке [«Словарь»](../guide/guides/dictionary.md#adding-and-deleting-rows) каждое сочетание привязки `addColumn` из одного нажатия вставляет под выделением столько строк, сколько охватывает выделение, то же сочетание с дополнительно зажатой клавишей `Shift` вставляет их над выделением, а каждое сочетание привязки `removeColumn` из одного нажатия удаляет строки, которые охватывает выделение: при значениях по умолчанию это `Alt+Enter`, `Alt+Shift+Enter` и `Alt+Backspace` или `Alt+Delete`. Они действуют в сетке листов `Domains`, `Words` и `Terms`, пока не открыто редактирование ячейки. Сочетание привязки `addColumn`, которое уже содержит `Shift`, не дает сочетания для вставки над выделением, а последовательность, привязанная к любому из этих имен, ничего не дает сетке.  
Для каждого такого нажатия действие по умолчанию отменяется так, как указано в его параметрах, а распространение всегда останавливается, поэтому оно не добавляет и не удаляет столбцы на вкладке ERD. На листе `Checks` и в редакторе только для чтения оно ничего не делает, хотя действие по умолчанию по-прежнему отменяется и распространение останавливается. В открытом поле редактирования ячейки или в поле поиска вкладки сочетания остаются тексту: там распространение останавливается, но действие по умолчанию не отменяется, поэтому поле обрабатывает их так же, как в любом другом месте (на Mac `⌥ + Backspace` удаляет слово). Их перечисляет [dictionaryRowChords](#dictionaryrowchords).

Начиная с версии `3.10.0` привязка `findReplace` (`$mod+KeyF`) открывает [Поиск и замену](../guide/guides/find-and-replace.md). Начиная с версии `4.1.0` она открывает и закрывает [Обозреватель](../guide/guides/explorer.md#opening-and-closing), в котором находится Поиск и замена, а вкладка «Сочетания клавиш» показывает ее как `Toggle Explorer`.  
Пока кнопка `Explorer` на панели инструментов отображается нажатой (Обозреватель открыт на вкладке ERD и не скрыт режимом дзен), привязка закрывает Обозреватель, если только не открыт быстрый поиск, окно «Свойства таблицы», конструктор темы, окно выбора языка интерфейса, окно `Export image` или `Map Columns`. В противном случае она закрывает то из них, что открыто, переключает на вкладку ERD с любой другой вкладки и открывает Обозреватель с курсором ввода в поле `Find` и выделенным запросом. Редактор, слишком узкий, чтобы показать Обозреватель рядом с холстом, оставляет его открытым, но скрытым, и показывает уведомление `Widen the window to show the Explorer`. До версии `4.1.0` она открывала плавающую панель Поиска и замены или возвращала фокус клавиатуры в ее поле и никогда ее не закрывала.  
Она не уступает курсору ввода: пока редактор в фокусе, она срабатывает на любой вкладке — с холста или из поля ввода внутри редактора. Действие по умолчанию для нажатия отменяется, поэтому браузер не открывает панель поиска, а распространение останавливается, поэтому ни один обработчик `keydown` на странице в фазе всплытия его не получает. Если открыто поле редактирования ячейки или заметки, начиная с версии `4.0.0` — поле редактирования имени группы таблиц либо начиная с версии `4.2.0` — редактирование ячейки в сетке вкладки «Словарь», действие по умолчанию по-прежнему отменяется и распространение останавливается, но привязка ничего не делает. В последнем случае привязка `search` тоже ничего не делает, поэтому уже введенный текст сохраняется.  
Пока открыт просмотр различий, путешествие во времени или предварительный просмотр Автоматического размещения, на какой бы вкладке это ни было, или пока метод ввода (IME) еще выполняет набор, для нажатия не отменяется действие по умолчанию и не останавливается распространение, поэтому его получает собственный поиск браузера или хоста. Внутри Обозревателя распространение нажатия, сделанного во время набора, останавливается, хотя действие по умолчанию не отменяется. Любое сочетание, на которое вы переназначите `findReplace`, ведет себя так же.

Привязка `focusView` действует только на вкладке ERD. Если выделена хотя бы одна таблица, она открывает вкладку «Визуализация» в режиме Flow с видом, суженным до этих таблиц и всех таблиц на расстоянии одной связи от них; выделенная заметка или группа таблиц не учитывается, а если не выделено ни одной таблицы, привязка ничего не делает. См. [Фокус на таблицах](../guide/guides/visualization.md#focusing-on-tables).

Привязки `undo` и `redo` действуют в зависимости от вкладки. На вкладке ERD они отменяют и повторяют действия по истории изменений документа. Начиная с версии `4.2.0` на вкладке «Словарь» они отменяют и повторяют действия по собственной истории изменений открытого листа, а на листе `Checks` ничего не делают — см. [Листы словарей](../guide/guides/undo-redo.md#dictionary-sheets). В режиме Flow на вкладке «Визуализация» они делают шаг назад и вперед, как и кнопки [`Previous table` и `Next table`](../guide/guides/visualization.md#previous-table-and-next-table), не затрагивая историю изменений документа. На остальных вкладках и в режиме Graph они ничего не отменяют.

Привязка `stop` (`Escape`) на вкладке ERD закрывает открытое поле редактирования ячейки или заметки либо завершает рисование связи и оставляет выделение как есть. Начиная с версии `4.0.0` она также закрывает поле редактирования имени группы таблиц, не записывая имя, и завершает рисование группы `New Table Group`. Для этого нажатия редактор вызывает `preventDefault()`.  
Если ничего из этого не открыто, `Escape` снимает выделение и сбрасывает ячейку в фокусе, а действие по умолчанию не отменяется. Поэтому, чтобы выйти из редактирования и снять выделение, нужно нажать клавишу дважды.  
Начиная с версии `4.2.0`, пока у ячейки логического имени показан список терминов (см. [Автодополнение терминов](../guide/guides/logical-names.md#completing-term-names)), первое нажатие `Escape` закрывает только этот список и оставляет поле редактирования открытым. Для этого нажатия в ячейке отменяется действие по умолчанию и останавливается распространение, поэтому его не получает ни привязка `stop`, ни обработчик `keydown` на странице в фазе всплытия.  
Кроме Обозревателя, форматов `Import` на [экране приветствия](#enablewelcomescreen), списка терминов ячейки логического имени, вкладки [«Словарь»](../guide/guides/dictionary.md#keys-on-the-tab) и описанных ниже окон выбора и диалоговых окон, редактор никогда не останавливает распространение `Escape`, поэтому страница, которая сама отслеживает эту клавишу, например чтобы закрыть собственное окно, получает оба нажатия и может пропустить то, у которого `defaultPrevented` равен `true`.  
Пока открыт быстрый поиск, окно свойств таблицы, просмотр различий, предварительный просмотр Автоматического размещения или путешествие во времени, `Escape` вместо этого закрывает его и оставляет выделение как есть. Для этого нажатия действие по умолчанию тоже не отменяется.  
Начиная с версии `4.0.0` открытое окно [`Export image`](../guide/guides/file-import-export.md#image) или [`Map Columns`](../guide/guides/relationship-editing.md#map-columns) тоже обрабатывает `Escape`: оно закрывается и оставляет выделение как есть. Каждое из них при открытии получает фокус клавиатуры, и для такого нажатия `Escape` отменяется действие по умолчанию и останавливается распространение.  
Начиная с версии `4.1.0` нажатие `Escape`, когда фокус находится внутри [Обозревателя](../guide/guides/explorer.md#keys-in-the-explorer) — в его дереве, полях или кнопках, — возвращает фокус клавиатуры холсту, оставляя Обозреватель открытым, а выделение — без изменений. Редактор вызывает для него и `preventDefault()`, и `stopPropagation()`, поэтому оно никогда не доходит до обработчика `keydown` на странице в фазе всплытия.  
Нажатие `Escape` на холсте никогда не закрывает Обозреватель. До версии `4.1.0` нажатие `Escape` внутри панели Поиска и замены закрывало ее, а нажатие на холсте закрывало ее одновременно со снятием выделения.  
Начиная с версии `4.0.0` окно выбора языка интерфейса и окно выбора цвета закрываются по `Escape`: внутри них для нажатия отменяется действие по умолчанию и останавливается распространение, а на холсте нажатие закрывает их одновременно со снятием выделения, без отмены действия по умолчанию и без остановки распространения.  
Нажатие `Escape`, пока метод ввода (IME) еще выполняет набор, относится к набору. Оно оставляет открытое поле редактирования как есть, и действие по умолчанию не отменяется, поэтому страница также может пропустить нажатие, у которого `isComposing` равен `true` или `keyCode` равен `229`. Внутри Обозревателя распространение такого нажатия, как и любой клавиши, нажатой там во время набора, также останавливается, и фокус клавиатуры остается в поле.  
До версии `3.9.2` одно нажатие `Escape` и завершало редактирование или рисование, и снимало выделение, а редактор никогда не отменял для него действие по умолчанию.

### createKeyBindingMap {#createkeybindingmap}

Начиная с версии `3.9.2` пакет экспортирует функцию `createKeyBindingMap()`, а вместе с ней типы `KeyBindingMap`, `KeyBindingName` и `ShortcutOption`.  
Она возвращает привязки клавиш по умолчанию — все 28 имен, включая фиксированные, — при каждом вызове в виде новой карты, поэтому изменение возвращенной карты больше ничего не меняет.  
С этой карты начинает каждый редактор, а вызов `setKeyBindingMap` в ней не отражается.  
Из этих четырех только `createKeyBindingMap` экспортируется как значение времени выполнения; остальные три — типы. Начиная с версии `4.2.0` рядом с ней экспортируется и [dictionaryRowChords](#dictionaryrowchords).

```ts
type KeyBindingName =
  | 'edit'
  | 'stop'
  | 'search'
  | 'findReplace'
  | 'undo'
  | 'redo'
  | 'addTable'
  | 'addColumn'
  | 'addMemo'
  | 'addTableGroup'
  | 'groupSelectedTables'
  | 'removeTable'
  | 'removeColumn'
  | 'removeSelection'
  | 'primaryKey'
  | 'selectAllTable'
  | 'selectAllColumn'
  | 'relationshipZeroOne'
  | 'relationshipZeroN'
  | 'relationshipOneOnly'
  | 'relationshipOneN'
  | 'tableProperties'
  | 'focusView'
  | 'zoomIn'
  | 'zoomOut'
  | 'zoomReset'
  | 'handTool'
  | 'zenMode';

type KeyBindingMap = Record<KeyBindingName, ShortcutOption[]>;

declare function createKeyBindingMap(): KeyBindingMap;

// example
import { createKeyBindingMap } from '@dineug/erd-editor';

const shortcuts = Object.values(createKeyBindingMap())
  .flat()
  .map(({ shortcut }) => shortcut); // 'Enter', 'Escape', '$mod+KeyK', ...
```

Каждое значение `shortcut` — это сочетание клавиш в синтаксисе [tinykeys](https://github.com/jamiebuilds/tinykeys), где клавиша указывается по `KeyboardEvent.code`, а [`$mod`](#mod) означает `⌘` в macOS и `Control` в остальных системах.  
Начиная с версии `4.0.0` редактор разбирает эти сочетания сам, а не через tinykeys, в том же синтаксисе. Клавиша совпадает по своему `code` или по `key` в любом регистре, а нажатие совпадает, только если зажаты ровно те клавиши-модификаторы, которые указаны в сочетании. `AltGraph` считается нажатием `Control` и `Alt` в Windows и нажатием `Alt` в macOS. Нажатия, разделенные пробелом, образуют последовательность, которая начинается заново после секунды без события keydown.  
Начиная с версии `4.1.0` одна из привязок по умолчанию — последовательность: `groupSelectedTables` равна `KeyT KeyG`, т. е. `T`, затем `G`. Последовательность срабатывает на нажатии, которое ее завершает, и только к этому нажатию применяются ее `preventDefault` и `stopPropagation`, поэтому при значениях по умолчанию `T` доходит до страницы, а действие по умолчанию отменяется только для `G`. Меню, быстрый поиск и вкладка «Сочетания клавиш» показывают последовательность по одной клавише на каждое нажатие.  
Фиксированные имена привязаны к `Enter` (`edit`), `Escape` (`stop`), `$mod+KeyZ` (`undo`), `$mod+Shift+KeyZ` (`redo`), `$mod+Equal` (`zoomIn`), `$mod+Minus` (`zoomOut`) и `$mod+Digit0` (`zoomReset`). У `edit` и `stop` нет флагов; у остальных пяти есть `preventDefault` и `stopPropagation`. Остальные привязки — это значения по умолчанию, приведенные выше, в том числе `search` и `findReplace`.

Редактор отслеживает эти сочетания на собственном элементе, поэтому хост, который перехватывает клавиши раньше редактора — глобальными горячими клавишами или обработчиком `keydown` в фазе перехвата, — должен пропускать их, пока редактор в фокусе.  
Составляйте список пропускаемых сочетаний на основе `createKeyBindingMap()`, заменяя значения по умолчанию привязками, которые вы передали в `setKeyBindingMap`.  
Начиная с версии `3.10.0` в этот список входит `$mod+KeyF` — собственное сочетание поиска браузера. Хост, который хочет оставить на этом сочетании свой собственный поиск, вызывает `setKeyBindingMap({ findReplace: [] })`.  
Начиная с версии `4.0.0` в него также входят `Delete` и `Backspace` без модификаторов. Хост, который хочет оставить эти клавиши себе, вызывает `setKeyBindingMap({ removeSelection: [] })`.  
Начиная с версии `4.1.0` в него также входят `Alt+KeyG` и последовательность `KeyT KeyG`, которая приходит одной строкой: разделите ее по пробелу и пропускайте каждое нажатие, включая `T` и `G` без модификаторов, поскольку последовательность, в которой не хватает нажатия, никогда не завершается. Хост, который хочет оставить эти клавиши себе, вызывает `setKeyBindingMap({ addTableGroup: [] })` или `setKeyBindingMap({ groupSelectedTables: [] })`.  
Начиная с версии `4.2.0` добавьте в него сочетания, которые [dictionaryRowChords](#dictionaryrowchords) возвращает для той же карты, в том числе `Alt+Shift+Enter`. Хост, который хочет оставить эти клавиши себе, вызывает `setKeyBindingMap({ addColumn: [] })` или `setKeyBindingMap({ removeColumn: [] })`, что также снимает их с добавления и удаления столбцов на вкладке ERD.

Пока фокус находится внутри Обозревателя — в его дереве, полях `Find` и `Replace` или кнопках, — `findReplace`, `search`, `undo`, `redo`, `zoomIn`, `zoomOut` и `zoomReset` проходят к редактору, поэтому `findReplace` действует там так же, как на холсте. Все остальные привязки в их текущем виде останавливаются в Обозревателе (последовательность — на последнем нажатии, при значениях по умолчанию это `G` без модификаторов), как и клавиши со стрелками, `Tab`, `Enter`, `Space`, `Home`, `End` и любая клавиша, нажатая, пока метод ввода (IME) еще выполняет набор. Кроме клавиши `Escape`, которая возвращает фокус клавиатуры холсту, для них останавливается распространение без отмены действия по умолчанию, поэтому в полях, кнопках и дереве Обозревателя они работают как обычные клавиши и не доходят ни до холста, ни до обработчика `keydown` на странице в фазе всплытия: `Alt + N` там не добавляет таблицу, а `Delete` ничего не удаляет. Для клавиш, которые перемещают по строкам дерева, сворачивают их или переходят к ним, и для клавиши `Enter` в поле `Find` или `Replace`, которая перемещает по совпадениям или выполняет замену, также отменяется действие по умолчанию.  
Любая другая клавиша, например сочетание сохранения или палитры команд хоста, как обычно, проходит к странице. См. [Клавиши в Обозревателе](../guide/guides/explorer.md#keys-in-the-explorer). До версии `4.1.0` плавающая панель Поиска и замены удерживала клавиши так же, за исключением `Home`, `End`, последнего нажатия последовательности и `Space`, пока `handTool` был привязан к другой клавише.  
Начиная с версии `4.0.0` окно выбора языка интерфейса удерживает клавиши так же: те же семь привязок проходят дальше, а для всех остальных привязок (начиная с версии `4.1.0` для последовательности — по последнему нажатию), клавиш со стрелками и `Tab` там останавливается распространение без отмены действия по умолчанию, как и для любой клавиши, нажатой, пока метод ввода (IME) еще выполняет набор. `↑`, `↓`, `Home`, `End`, `Enter` и `Space` на одной из его строк перемещают по строкам или выбирают строку, и для них также отменяется действие по умолчанию.

Начиная с версии `4.2.0` клавиши удерживает и вкладка [«Словарь»](../guide/guides/dictionary.md#keys-on-the-tab), причем к редактору проходят только `search`, `findReplace`, `undo` и `redo`. Привязки `undo` и `redo` работают с собственной историей изменений открытого листа, а при открытом редактировании ячейки или при фокусе в поле поиска вкладки остаются тексту: там для них останавливается распространение, но не отменяется действие по умолчанию. Привязки `search` и `findReplace` ничего не делают, пока открыто редактирование ячейки, как описано выше. Сочетания клавиш для строк действуют в сетке, как описано выше для привязок `addColumn` и `removeColumn`.  
Все остальные привязки в их текущем виде останавливаются на вкладке (последовательность — на последнем нажатии), как и клавиши со стрелками, `Tab`, `Enter`, `Space`, `Home`, `End` и любая клавиша, нажатая, пока метод ввода (IME) еще выполняет набор. Ни одна из них не доходит ни до холста, ни до обработчика `keydown` на странице в фазе всплытия: `Alt + N` там не добавляет таблицу, а `Delete` ничего не удаляет из диаграммы. События копирования, вырезания и вставки на вкладке тоже останавливаются там, поэтому диаграмма никогда не принимает их за свои. Любая другая клавиша, как обычно, проходит к странице.

### dictionaryRowChords {#dictionaryrowchords}

Начиная с версии `4.2.0` пакет экспортирует функцию `dictionaryRowChords()`. При каждом вызове она возвращает в виде нового массива `ShortcutOption[]` все сочетания клавиш, которыми сетка вкладки «Словарь» вставляет или удаляет строки при переданной карте привязок клавиш.  
По порядку это сочетания привязки `addColumn` из одного нажатия, которые вставляют строки под выделением; те же сочетания с дополнительно зажатой клавишей `Shift`, которые вставляют строки над выделением, — кроме сочетания, которое уже содержит `Shift`; и сочетания привязки `removeColumn` из одного нажатия, которые удаляют строки. Каждое из них сохраняет `preventDefault` и `stopPropagation` привязки, из которой оно взято, а последовательность в список не входит. См. [Добавление и удаление строк](../guide/guides/dictionary.md#adding-and-deleting-rows).  
Сочетание, которое вставляет строки над выделением, — при значениях по умолчанию это `Alt+Shift+Enter` — не входит ни в одну привязку, поэтому хост, который сверяет клавиши-модификаторы точно и составляет список пропускаемых сочетаний только на основе [createKeyBindingMap](#createkeybindingmap), никогда его не пропускает. Пропускайте оба списка, как это делает плагин для Obsidian.  
Функция читает только переданную ей карту, а не привязки элемента, поэтому передавайте ей ту же карту, на основе которой вы составили список пропускаемых сочетаний.

  keyBindingMap: KeyBindingMap
): ShortcutOption[];

  ...Object.values(map).flat(),

## Тема {#theme}

### setPresetTheme {#setpresettheme}

Задает предустановленную тему.  
Значения по умолчанию: `appearance: 'dark'`, `grayColor: 'slate'` и `accentColor: 'indigo'`.  
Каждое поле применяется отдельно, поэтому частичный вызов оставляет два других поля как есть. Значение, которое не входит в перечисленные ниже имена, игнорируется, и вызов никогда не выбрасывает исключение.  
Начиная с версии `4.0.0` поле `appearance` также принимает `'system'` — вариант `System` конструктора темы. Он показывает светлое или темное оформление, о котором сообщает операционная система или которое задает [setSystemAppearance](#setsystemappearance), и переключается при его изменении.

### setSystemAppearance {#setsystemappearance}

Начиная с версии `4.0.0` задает светлый или темный вариант, который показывает оформление `'system'`, — для хоста с собственными светлым и темным вариантами, например темой IDE. Пока вариант задан, изменения в операционной системе игнорируются.  
`null` или любое значение, кроме `'dark'` и `'light'`, возвращает к следованию за операционной системой.  
Пока оформление равно `'light'` или `'dark'`, метод ничего не меняет на экране, но значение сохраняется и применяется, как только оформление становится `'system'`. В противном случае оно применяется сразу. Метод ничего не генерирует, а `changePresetTheme` по-прежнему сообщает `'system'`.  
Хосты VS Code, JetBrains и Obsidian вызывают его со своим светлым или темным оформлением и повторно при каждом его изменении.

```js
editor.setPresetTheme({ appearance: 'system' });
editor.setSystemAppearance('light'); // null follows the OS again
```

### setTheme {#settheme}

Позволяет настроить тему.  
Каждый вызов заменяет весь пользовательский слой целиком, поэтому, чтобы изменить один токен поверх уже заданного переопределения, снова передайте полный объект, а чтобы вернуться к предустановленной теме, передайте `{}`.  
Сохраняются только перечисленные ниже имена токенов со строковыми значениями; все остальное отбрасывается без ошибки.

`tableShadow` и `memoShadow` задают цвет тени, которую таблицы и заметки отбрасывают на холст ERD. Темная предустановленная тема оставляет их `transparent`, и тень не отбрасывается, как и при передаче `none` или пустой строки в `setTheme`; светлая предустановленная тема использует `rgba(0, 0, 0, 0.18)`.

Начиная с версии `4.0.0` есть еще девять токенов:

- `tableGroupHeaderBackground`, `tableGroupBackground` и `tableGroupBorder` задают цвет строки заголовка, тела и контура [группы таблиц](../guide/guides/table-groups.md), у которой нет собственного цвета.
- `toastSuccess` и `toastError` задают цвет значка уведомления, которое сообщает, чем что-то закончилось.
- `findReplaceError` и `mapColumnsError` задают цвет ошибок, которые показывают Поиск и замена и окно «Сопоставить столбцы». Раньше Поиск и замена использовал `diffDeleteForeground`, поэтому переопределение этого токена его больше не перекрашивает.
- `schemaSqlWarningBackground` и `schemaSqlWarningForeground` задают цвет предупреждений в параметрах вкладки «Схема SQL».

Начиная с версии `4.1.0` есть еще девять токенов:

- `treeBackground`, `treeRowHover`, `treeRowCurrent`, `treeMuted` и `treeMatch` задают цвета дерева, общего для [Обозревателя](../guide/guides/explorer.md#the-tree) и [Просмотра различий](../guide/guides/table-related-functions.md#diff-viewer): его фона, которым также заливаются поля `Find` и `Replace` Обозревателя; строки под указателем, строки, выбранной с клавиатуры, пока дерево в фокусе, и кнопки под указателем в заголовке и поиске Обозревателя; строки текущего совпадения поиска; приглушенного текста, например счетчиков, типов данных и стрелок сворачивания; и подсветки под текстом, найденным поиском.
- `explorerBackground` и `explorerBorder` задают цвета панели Обозревателя и ее линий: края рядом с холстом, линии под поиском и границ полей и кнопок, которые раскрывает `Search In`. `explorerBorder` также рисует край дерева Просмотра различий, линию под его полем `Filter by name` и границу этого поля. Значки ключей в Обозревателе используют `keyPK`, `keyFK` и `keyPFK`.
- `diffModifyForeground` и `diffRenameForeground` задают цвет того, что Просмотр различий помечает как измененное и переименованное, в его дереве и на обоих документах. `diffModifyForeground` также обводит таблицу, заметку или группу таблиц, которую переместили, у которой изменили размер, цвет или группу, что бы еще в ней ни изменилось, и рисует линию связи измененного внешнего ключа.

`diffInsertForeground` и `diffDeleteForeground` теперь задают цвет того, что Просмотр различий помечает как добавленное и удаленное, в его дереве и на документе, который это содержит, — одинаково в тексте, контурах и линиях связи. `diffInsertBackground`, `diffDeleteBackground`, `diffCrossBackground` и `diffCrossForeground` удалены в версии `4.1.0`, так как Просмотр различий больше не заливает ячейки. `setTheme` отбрасывает их, как и любое другое имя, которого нет в `Theme`, а их переменные CSS `--erd-editor-diff-insert-background`, `--erd-editor-diff-delete-background`, `--erd-editor-diff-cross-background` и `--erd-editor-diff-cross-foreground` больше не читаются.

Начиная с версии `4.2.0` есть еще двенадцать токенов:

- `columnHandleBackground` и `columnHandleBorder` задают заливку и контур [маркера перетаскивания столбца](../guide/guides/table-editing.md#rearranging-and-moving-columns), который рисуется сразу за левым краем таблицы рядом со строкой столбца в фокусе, а `columnHandleHoverBackground` и `columnHandleHoverBorder` заменяют их, пока на маркере находится указатель. Его значок захвата использует `foreground`, а под указателем — `active`.
- `dictionaryErrorForeground` и `dictionaryWarningForeground` задают цвет того, что находят [проверки словарей](../guide/guides/dictionary.md#what-each-check-finds), — ошибки или предупреждения: помеченного имени на холсте ERD (см. [Пометки на холсте](../guide/guides/dictionary.md#marks-on-the-canvas)), текста помеченной ячейки на листах `Domains`, `Words` и `Terms` и счетчика листа `Checks`. `dictionaryErrorBackground` и `dictionaryWarningBackground` задают фон такой ячейки. `dictionaryErrorForeground` также задает цвет инструмента `Delete Rows` под указателем.
- `dictionaryBackground`, `dictionaryHeaderBackground`, `dictionaryGridLine` и `dictionaryHeaderSelect` задают цвета листа вкладки [«Словарь»](../guide/guides/dictionary.md#the-sheets): его ячеек, цветом которых также заливаются поле поиска вкладки и список доменов термина; его заголовков столбцов и номеров строк; линий между ячейками, цветом которых также рисуются панель вкладки и границы ее полей; и заголовка, строка или столбец которого попадает в выделение. Остальная часть листа использует общие токены: `foreground` — для подписей заголовков, `active` — для текста ячеек, `grayColor7` — для линии, отделяющей заголовки столбцов и номера строк от ячеек, `focus` — для края активной ячейки, `accentColor9` — для края выделенного диапазона и, с непрозрачностью 20%, для его заливки, `accentColor6` — для заголовка целиком выделенной строки или столбца, `grayColor3` — для ячеек только для чтения, а также токены полосы прокрутки. Если `accentColor9` записан не в виде `#rgb` или `#rrggbb`, выделенный диапазон остается без заливки.

#### Переменные CSS {#css-variables}

Каждому токену в `Theme` соответствует переменная CSS, имя которой состоит из `--erd-editor-` и ключа в стиле kebab-case: `grayColor10` — это `--erd-editor-gray-color-10`, `keyPK` — `--erd-editor-key-pk`, а `keyPFK` — `--erd-editor-key-pfk`.  
Эти переменные наследуются внутрь редактора, поэтому задавайте их там, где они должны действовать. На `:root` они задают тему всем редакторам на странице, а на самом элементе — только этому редактору.

```css
erd-editor {
  --erd-editor-canvas-background: #1b1b1f;
}
```

Начиная с версии `3.4.0` токены с опечаткой `dargSelect` пишутся как `dragSelect`, а их переменные CSS изменились с `--erd-editor-darg-select-background` и `--erd-editor-darg-select-border` на `--erd-editor-drag-select-background` и `--erd-editor-drag-select-border`. ## Язык интерфейса {#display-language}

Начиная с версии `4.0.0` собственный текст редактора — меню, панели, окна, быстрый поиск, уведомления и слова, которые он рисует на диаграмме, например `unnamed`, в том числе при экспорте изображений, — доступен на 25 языках. Имена таблиц и столбцов, SQL, типы данных и сгенерированный код никогда не переводятся. См. [Язык и тема](../guide/guides/language-and-theme.md).  
Пока не вызван [setLocale](#setlocale) и не выбран язык, редактор показывает английский или, если включен [enableLocalePicker](#enablelocalepicker), следует `'system'`.  
Редактор задает `lang` и `dir` на собственном корневом элементе внутри закрытого теневого корня и никогда на элементе-хосте или странице, поэтому страница с письмом справа налево не переворачивает редактор, а язык с письмом справа налево не переворачивает страницу. На иврите, арабском и персидском интерфейс редактора располагается справа налево; сама диаграмма никогда не отражается зеркально. Начиная с версии `4.1.0` [Обозреватель](../guide/guides/explorer.md) на любом языке остается слева от холста, а его собственные строки на этих трех языках читаются справа налево.  
Пакет экспортирует типы `LocaleCode` (один из кодов ниже) и `LocaleOption`.

### setLocale {#setlocale}

Задает язык интерфейса: `'system'` или один из кодов выше. Все остальное, например просто `'ko'`, неизвестный код или значение, не являющееся строкой, игнорируется без ошибки.  
Он применяется до возврата из вызова, поэтому язык, заданный до добавления элемента на страницу, виден уже в первом кадре.  
Он ничего не генерирует — ни `changeLocale`, ни `change` — и не затрагивает ни `value`, ни историю изменений, ни общее хранилище.  
Выбор сохраняется независимо от того, включен `enableLocalePicker` или выключен, а `setLocale('system')` следует за системой и при выключенном выборе языка.  
Редактор ничего не сохраняет. Чтобы запомнить выбор пользователя, отслеживайте [changeLocale](#changelocale) и передавайте выбор обратно при следующей загрузке.

```js
editor.enableLocalePicker = true;
editor.setLocale(localStorage.getItem('locale') ?? 'system');
editor.addEventListener('changeLocale', event => {
  localStorage.setItem('locale', event.detail.locale);
});
```

### setSystemLocale {#setsystemlocale}

Задает язык, который обозначает `'system'`, в виде тега BCP 47 — для хоста с собственным языком интерфейса. Хосты VS Code, JetBrains и Obsidian вызывают его со своим языком интерфейса.  
Пробелы по краям тега обрезаются. `null`, пустая строка или значение, не являющееся строкой, возвращает к `navigator.languages` браузера, за изменениями которого редактор следит.  
Он имеет значение, только пока действует вариант `'system'`, и применяется сразу. Строка `System` в окне выбора называет язык, в который он разрешается.  
Тег или каждый из языков браузера по порядку разрешается в первый язык, который есть в редакторе, по подтегу языка, без учета регистра и символов подчеркивания: `de-AT` дает `de-DE`, а `en-GB` — `en`. Китайский определяется по письменности (`Hant` дает `zh-TW`, а `Hans` — `zh-CN`), а без нее — по региону: `TW`, `HK` и `MO` дают `zh-TW`, а любой другой — `zh-CN`. `pt` дает `pt-BR`, если не указан регион, отличный от `BR`. Если ничего не подходит, редактор показывает английский.

```js
editor.setLocale('system');
editor.setSystemLocale('pt-PT'); // null follows the browser again
```

## setSchemaSQL {#setschemasql}

Загружает файл Схемы SQL.  
По умолчанию он заменяет текущий документ, а не объединяется с ним; см. `mode` ниже. Уже заданные настройки сохраняются, включая каждую блокировку и ее заблокированное значение, кроме положения вида и масштаба, а таблицы размещаются после чтения файла — рядами, если `placement` ниже не требует иного. Если `Viewport` заблокирован, `value` затем записывает вид, с которого начинается импорт: начало координат `0, 0` при масштабе `1`. Поэтому в документе, импортированном в элемент, которому никогда не задавалось значение, включены все блокировки, как и в новом документе.  
Начиная с версии `4.2.0` замена также сохраняет слова, термины и домены документа, которые текст не может содержать, вместе с историей изменений каждого листа вкладки «Словарь», и отмена или повтор импорта тоже их сохраняет. [setSchemaJSON](#setschemajson) в режиме замены и присваивание `value`, напротив, берут те, что содержит их документ.  
Он записывается в историю изменений, что позволяет выполнить `Undo, Redo`, и генерирует `change`. Пустая строка игнорируется, а пока установлен атрибут `readonly`, вызов ничего не делает.  
`setSchemaGraphQL`, `setSchemaDBML` и `setSchemaAML` ведут себя так же, а их парсеры никогда не завершаются с ошибкой: текст, который они не могут прочитать, загружает пустой документ, а не вызывает ошибку.  
Начиная с версии `4.0.0` все четыре метода принимают необязательный второй аргумент `{ placement, mode }`:

- `placement: 'grid'`, значение по умолчанию, сразу размещает таблицы рядами, как и раньше, и вызов ничего не возвращает.
- `placement: 'auto'` сначала размещает таблицы с учетом их связей, как это делает `Import` в редакторе, и возвращает `Promise`, который разрешается, когда импорт применен как один шаг отмены. Если таблиц меньше двух, связей нет, размещение не удалось, на странице нет `SharedWorker` или в уведомлении `Placing tables` нажата кнопка `Cancel`, таблицы вместо этого размещаются рядами. Загрузка, произошедшая за это время, — другой заменяющий импорт, присваивание `value`, `setInitialValue()`, `clear()`, загрузка соавтора либо отмена или повтор загрузки или `clear()` — вытесняет его, и `Promise` разрешается, ничего не загрузив. Импорты, размещаемые таким способом, применяются в том порядке, в котором они начались.
- `mode: 'replace'`, значение по умолчанию, заменяет документ. `mode: 'append'` добавляет файл под диаграммой, как [Импорт с добавлением](../guide/guides/file-import-export.md#import-and-add), оставляя как есть все уже имеющиеся таблицы и все настройки, кроме вкладки и положения вида. Если открыта другая вкладка, сначала открывается вкладка ERD. Новые таблицы, а также группы таблиц, которые приносит файл DBML, пока группы таблиц показаны, становятся выделением, и вид прокручивается к ним, если они еще не видны как следует, по правилу, которому начиная с версии `4.1.0` следует каждый переход, — см. [Куда ведет переход](../guide/guides/table-related-functions.md#where-a-jump-lands). Одна отмена удаляет все добавленное. Текст, который не удается прочитать, ничего не добавляет и оставляет документ как есть.

Пока установлен атрибут `readonly`, замена игнорируется, добавление ничего не добавляет, а вызов с `placement: 'auto'` сразу разрешается.  
Начиная с версии `3.10.0` метод `setSchemaSQL` читает файл с учетом текущей базы данных документа: если выбрана СУБД Databricks, строки в одинарных кавычках следуют правилам экранирования обратной косой чертой, принятым в Spark. См. [Комментарии](../guide/guides/file-import-export.md#comments).  
Начиная с версии `3.10.0` метод `setSchemaSQL` читает `UNIQUE` по двум и более столбцам как один уникальный индекс, а не как флаг «Уникальный» у каждого столбца. См. [Уникальные ключи и индексы](../guide/guides/file-import-export.md#unique-keys-and-indexes).  
Начиная с версии `3.10.0` импорт SQL, DBML и AML сохраняет действия `ON DELETE` и `ON UPDATE` прочитанных внешних ключей.  
Начиная с версии `4.0.0` метод `setSchemaSQL` сохраняет выражение `DEFAULT` столбца целиком, читает `ADD DEFAULT … FOR` из SQL Server и его комментарии `MS_Description`, превращает столбцы serial и identity из PostgreSQL в Автоинкремент, сохраняет `UNSIGNED` и `ZEROFILL` в типе данных и читает первичный ключ, который `ALTER TABLE … ADD PRIMARY KEY` помечает как `CLUSTERED`, `NONCLUSTERED` или `USING BTREE`. См. [Схема SQL](../guide/guides/file-import-export.md#schema-sql).  
О синтаксисе, который принимает каждый парсер, см. [Импорт и экспорт файлов](../guide/guides/file-import-export.md).

```ts
type SetSchema = {
  (
    value: string,
    options: { placement: 'auto'; mode?: 'replace' | 'append' }
  ): Promise<void>;
  (
    value: string,
    options?: { placement?: 'grid'; mode?: 'replace' | 'append' }
  ): void;
};

// example
editor.setSchemaSQL('Schema SQL...');
// or
await editor.setSchemaSQL('Schema SQL...', { placement: 'auto' });
// or
editor.setSchemaSQL('Schema SQL...', { mode: 'append' });
```

## setSchemaJSON {#setschemajson}

Начиная с версии `4.0.0` загружает документ `.erd.json`, например текст, который возвращает [value](#value).  
В режиме по умолчанию `mode: 'replace'` он загружает документ так же, как присваивание `value`: загрузка записывается в историю изменений, генерирует `change` и так же принимает блокировки документа, а начиная с версии `4.2.0` слова, термины и домены документа заменяют те, что есть в редакторе. В отличие от `value`, пустая строка или значение, не являющееся строкой, игнорируется, а не начинает новый документ. Текст, не являющийся JSON, очищает документ, как и в случае с `value`.  
`mode: 'append'` добавляет таблицы, связи, индексы, заметки и группы таблиц документа под диаграммой с новыми идентификаторами, сохраняя их взаимное расположение и не учитывая настройки документа, как [Импорт с добавлением](../guide/guides/file-import-export.md#import-and-add) с файлом `json`. Начиная с версии `4.2.0` он сохраняет логические имена и флаги сформированных имен таблиц и столбцов, но не переносит слова, термины и домены документа, поэтому ни один из его столбцов не привязывается к домену. Текст, который не удается прочитать, или документ без таблиц и заметок ничего не добавляет. В остальных случаях добавление применяется так же, как добавление в [setSchemaSQL](#setschemasql), причем новые заметки и группы таблиц выделяются вместе с таблицами — каждый вид, пока он показан.  
Он возвращает управление, когда документ применен, и игнорируется, пока установлен атрибут `readonly`.

```js
editor.setSchemaJSON('json...');
// or
editor.setSchemaJSON('json...', { mode: 'append' });
```

## getSchemaSQL {#getschemasql}

Экспортирует текущее состояние редактора в виде Схемы SQL.  
Если `databaseVendor` не указан, запись идет для СУБД, которую показывает редактор: для СУБД документа, если только читатель редактора [только для чтения](#readonly) не выбрал другую, которая с версии `5.0.0` остается на этом экране и именно ее показывает его вкладка «Схема SQL». Имя, которого нет в списке ниже, обрабатывается так же, без ошибки.  
Имена заключаются в кавычки того типа, который показывает редактор. Пока `Bracket Type` [заблокирован](../guide/guides/settings.md#lock) или, начиная с версии `5.0.0`, в редакторе только для чтения, читатель которого выбрал другой, этот тип может отличаться от того, который сохраняет `value`, — именно с ним заключает имена в кавычки [`erd_read`](../mcp/tools.md#reading-a-document) агента для программирования. Записываемые имена — всегда физические, каким бы ни был режим отображения имен.  
Начиная с версии `4.0.0` необязательный аргумент `options` выбирает операторы и заголовок, как это делают параметры вкладки [«Схема SQL»](../guide/guides/schema-sql.md), а начиная с версии `4.2.0` — и то, заполняют ли логические имена пустые комментарии. `SchemaSQLOptions` экспортируется как тип.

- `statements`: `'create'` — значение по умолчанию; `'ifNotExists'`, который пишет `IF NOT EXISTS` в MySQL, MariaDB, PostgreSQL, SQLite и Databricks, а в остальных СУБД переходит на `'create'`; или `'recreate'`, который удаляет таблицы перед их созданием, а для Snowflake вместо этого пишет `CREATE OR REPLACE TABLE`.
- `header`: `'none'` — значение по умолчанию; `'use'`, который переключается на базу данных или схему документа; или `'createAndUse'`, который сначала создает ее, если она не существует, а затем переключается на нее. СУБД, в которой нет запрошенного варианта, переходит на запасной так же, как вкладка: Oracle пишет `'use'` вместо `'createAndUse'`, PostgreSQL не пишет заголовок для `'use'`, а SQLite не пишет его вовсе. Заголовок пишется, только если имя базы данных документа — простой идентификатор: буквы ASCII, цифры и `_`, без цифры в начале.
- `logicalNameAsComment`, начиная с версии `4.2.0`: `true` записывает логическое имя таблицы или столбца в качестве комментария там, где их собственный комментарий пуст или состоит из одних пробелов, а логическое имя — нет, в той форме, в которой эта СУБД пишет комментарии. Комментарий с текстом записывается как раньше. Включает параметр только `true`: если он пропущен, равен `false` или любому другому значению, например `'true'` или `1`, логические имена не записываются. Он делает то же, что и переключатель [`Write logical names into empty comments`](../guide/guides/schema-sql.md#logical-names-as-comments) на вкладке.

Пропущенный параметр или параметр с неизвестным значением считается равным значению по умолчанию, поэтому вызов без параметров пишет обычные операторы `CREATE` без заголовка, как и раньше.  
Начиная с версии `4.0.0` вывод всегда включает скрипты документа `Before tables` и `After tables` в таком порядке: заголовок, скрипт перед таблицами, операторы удаления, таблицы, скрипт после таблиц. Собственные параметры `Statements`, `Header`, `Write logical names into empty comments` и `Tables` вкладки «Схема SQL» никогда не влияют на этот вызов, который всегда пишет весь документ.  
Начиная с версии `3.10.0` каждый внешний ключ содержит предложения `ON DELETE` и `ON UPDATE` связи. Предложение пишется, только если его действие задано и СУБД его поддерживает, поэтому действие, которое эта СУБД не принимает, опускается и применяется ее значение по умолчанию. Начиная с версии `4.0.0` Snowflake принимает только `NO ACTION`. О том, что пишет каждая СУБД, см. [ON DELETE и ON UPDATE](../guide/guides/relationship-editing.md#on-delete-and-on-update).  
Начиная с версии `3.10.0` одинарная кавычка внутри комментария таблицы или столбца экранируется, поэтому комментарий вроде `it's` больше не ломает оператор. Каждая СУБД, которая пишет комментарии как строковые литералы, удваивает ее, кроме Databricks, которая ставит обратную косую черту перед каждой кавычкой и каждой обратной косой чертой. SQLite по-прежнему пишет комментарии строками `--`.  
Начиная с версии `4.2.0` SQL Server пишет каждый комментарий как национальный литерал `N'…'`, поэтому текст за пределами кодовой страницы базы данных, например корейский, сохраняется. Oracle пишет каждую последовательность пустых строк в комментарии как один перевод строки, а SQLite пишет переводы строк комментария как пробелы, поэтому комментарий остается на своей строке `--`. См. [Комментарии](../guide/guides/schema-sql.md#comments).  
Начиная с версии `4.0.0` несколько СУБД также по-другому пишут имена ключей, значения по умолчанию и автоинкремент. См. [Что содержит DDL](../guide/guides/schema-sql.md#what-the-ddl-writes).

```ts
type DatabaseVendor =
  | 'Databricks'
  | 'MariaDB'
  | 'MSSQL'
  | 'MySQL'
  | 'Oracle'
  | 'PostgreSQL'
  | 'Snowflake'
  | 'SQLite';

type SchemaSQLOptions = {
  statements?: 'create' | 'ifNotExists' | 'recreate';
  header?: 'none' | 'use' | 'createAndUse';
  logicalNameAsComment?: boolean;
};

const schemaSQL = editor.getSchemaSQL();
// or
const postgresSQL = editor.getSchemaSQL('PostgreSQL');
// or
const mysqlSQL = editor.getSchemaSQL('MySQL', {
  statements: 'ifNotExists',
  header: 'createAndUse',
});
// or
const commentedSQL = editor.getSchemaSQL('PostgreSQL', {
  logicalNameAsComment: true,
});
```

## getSharedStore {#getsharedstore}

Возвращает хранилище для совместного редактирования в реальном времени.  
`config` имеет вид `{ getNickname?, mouseTracker?, focusTracker? }`. Оба трекера по умолчанию равны `true`: `mouseTracker` транслирует курсор этого редактора остальным, а `focusTracker` — его ячейку в фокусе, выделение и рамку выделения.  
Начиная с версии `5.0.0` хранилище не отправляет изменений, пока установлен [readonly](#readonly), а только то, что отправляют его трекеры, и регистры, которые запрашивает присоединяющийся редактор, и по-прежнему применяет то, что присылают остальные.  
См. [Совместное редактирование](./advanced/collaborative-editing.md).

```js
const sharedStore = editor.getSharedStore({
  mouseTracker: false,
  focusTracker: false,
});
```

## setDiffValue {#setdiffvalue}

Открывает Просмотр различий, сравнивая открытый сейчас документ с переданным.  
Он ничего не возвращает и не изменяет документ, поэтому после закрытия окна просмотра редактор остается точно таким же, каким был.  
Пустое значение или любое значение, не являющееся строкой, сравнивается с пустым документом.  
Это то же окно, которое открывает пункт [Просмотр различий](../guide/guides/table-related-functions.md#diff-viewer) в контекстном меню холста.  
Начиная с версии `4.1.0` он сопоставляет содержимое двух документов сначала по идентификатору и только затем по тому, что хранит каждый элемент, например по имени таблицы или тексту заметки, — см. [Что сравнивается](../guide/guides/table-related-functions.md#what-is-compared). Поэтому при сравнении с более ранней версией того же документа, например с ревизией его файла в Git, переименование отображается как один переименованный элемент, а при сравнении с документом с другими идентификаторами — как удаление и добавление. Окно просмотра показывает изменения в дереве рядом с двумя документами и выделяет их цветом, а не заливкой ячеек.  
Начиная с версии `4.2.0` оба документа открываются в режиме отображения имен, который показывает этот редактор, какой бы режим ни сохранил переданный документ, и дерево тоже называет таблицы и столбцы по этому режиму — см. [За пределами холста](../guide/guides/logical-names.md#beyond-the-canvas). Логические имена, привязки к доменам и словари не сравниваются, поэтому изменение только в них не отображается как изменение.

```js
editor.setDiffValue('prev json...');
```
