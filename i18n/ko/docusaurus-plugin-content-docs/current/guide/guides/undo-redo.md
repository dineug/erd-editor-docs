# Undo, Redo

이전 편집 상태로 되돌아가거나 이후 상태로 이동할 수 있습니다.  
히스토리 최대 크기는 `2048`개 변경사항입니다.

- Undo: `Ctrl + Z` (Windows/Linux) or `⌘ + Z` (Mac)
- Redo: `Ctrl + Shift + Z` (Windows/Linux) or `⌘ + Shift + Z` (Mac)

툴바에도 동일한 두 명령이 `Time Travel` 옆에 `Undo`, `Redo` 버튼으로 있습니다.  
되돌리거나 다시 실행할 내용이 있을 때만 활성화됩니다. `readonly` 에디터에서는 세 버튼이 모두 숨겨지고 단축키도 동작하지 않습니다.

Undo, Redo는 ERD 탭에서만 동작합니다. Visualization, Schema SQL, Code Generator, 설정 탭에서는 사용할 수 없습니다.  
빠른 검색, 테이블 속성, Diff Viewer, 자동 배치 미리보기, Time Travel이 열려 있는 동안에도 단축키가 동작하지 않습니다.  
[찾기와 바꾸기](./find-and-replace.md#패널의-키)가 열려 있는 동안에는 단축키가 계속 동작합니다. 커서가 Find 또는 Replace 입력란에 있어도 입력란의 텍스트가 아니라 다이어그램을 되돌리고 다시 실행합니다.

히스토리는 현재 세션의 메모리에만 유지됩니다. 문서에 저장되지 않으므로 다이어그램을 다시 열면 히스토리는 비어 있는 상태로 시작합니다.

![테이블 이동과 컬럼 삭제를 ⌘ + Z로 되돌리고 ⌘ + Shift + Z로 다시 실행](/img/demo-undo-redo.webp)

## 히스토리에 기록되는 내용

기록되는 항목:

- 테이블과 메모: 추가, 삭제, 이동, 색상, 이름과 코멘트, 메모 텍스트와 크기.
- 컬럼: 추가, 삭제, 순서 변경, 그리고 모든 컬럼 옵션.
- 관계: 추가, 삭제, 타입 변경, 그리고 `On Delete`나 `On Update`에서 고른 각 항목. [ON DELETE와 ON UPDATE](./relationship-editing.md#on-delete와-on-update) 문서를 참고하세요. 삭제를 되돌리면 관계가 ON DELETE와 ON UPDATE 동작까지 그대로 복원됩니다.
- 인덱스와 인덱스 컬럼.
- 화면 위치, 확대/축소 레벨, `View Option` 토글.
- 파일 가져오기.

기록되지 않는 항목:

- 데이터베이스 벤더와 데이터베이스 이름.
- Code Generator 언어, `Table Name Case`, `Column Name Case`.
- Schema SQL 괄호 타입.
- 설정 탭의 모든 항목.
- Visualization 탭에서 두 모드의 확대/축소와 화면 이동, 그래프 노드나 Flow 카드 이동, `Tidy Up`, 행 표시, 테이블 포커스. [Flow는 문서를 편집하지 않음](./visualization.md#flow는-문서를-편집하지-않음) 문서를 참고하세요.

이 항목들의 변경은 되돌릴 수 없습니다.

다른 에디터에서 도착한 변경사항도 기록되지 않으므로, Undo는 자신의 변경만 되돌립니다. [공동 편집](../../api/advanced/collaborative-editing.md) 세션에서는 각 에디터가 자신의 변경을 되돌리며, [MCP 서버](../../mcp/live-and-headless.md#undo)로 편집하는 코딩 에이전트는 `erd_undo`로 자신의 변경을 되돌립니다.

파일 가져오기를 되돌리면 이전 다이어그램이 자신의 파일에 저장될 때의 모습 그대로 돌아옵니다.  
그 다이어그램의 [`Save Scroll Information`](./settings.md#스크롤-정보-저장)이 꺼져 있으면 화면은 보고 있던 위치가 아니라 다이어그램이 열리는 위치로 돌아갑니다. [`Save Zoom Information`](./settings.md#확대축소-정보-저장)이 꺼져 있으면 확대/축소는 `100%`로 돌아갑니다. 편집 내용 자체는 어느 경우든 복원됩니다.  
새 다이어그램은 두 스위치가 모두 꺼진 상태로 시작합니다. 이런 되돌리기에서도 화면을 유지하려면 두 스위치를 켜세요.

## 동작 하나가 한 단계

하나의 동작이 발생시킨 모든 변경은 히스토리 항목 하나가 됩니다.  
여러 테이블과 메모를 한 번에 붙여넣거나 `Alt + drag`로 복제한 것은 한 단계로 되돌려집니다.

[찾기와 바꾸기](./find-and-replace.md#바꾸기)의 `Replace All`도 바꾸는 테이블 이름, 코멘트, 컬럼 이름, 메모가 몇 개든 한 단계입니다. 아무것도 바꾸지 않으면 단계를 기록하지 않습니다.  
`Replace` 한 번도 한 단계이며, 다음 일치 항목으로 가는 데 스크롤이 필요하면 그 스크롤도 같은 단계에 포함됩니다.  
패널 옆에 아직 완전히 보이지는 않는 일치 항목으로 이동하면 캔버스가 스크롤되며, 이 스크롤은 다른 화면 위치 변경과 마찬가지로 기록됩니다. [일치 항목으로 이동](./find-and-replace.md#일치-항목으로-이동) 문서를 참고하세요. 일치 항목 사이를 이동한 뒤에는 Undo가 먼저 그 스크롤들을 한 단계에 하나씩 되돌립니다.

연속된 드래그, 캔버스 이동, 확대/축소, 핀치, 색상 변경도 약 `200ms` 동안 버퍼링되어 항목 하나로 기록됩니다.  
전체 이동 거리가 `20px` 미만인 드래그는 아예 기록되지 않습니다.

셀이나 메모에 입력하는 내용은 동작 단위가 아니라 입력 단위로 기록됩니다. 입력한 글자 하나, 붙여넣기 한 번, IME 조합의 각 단계가 각각 한 단계가 됩니다.

## Time Travel

툴바의 Undo, Redo 옆에 있는 `Time Travel` 버튼으로 열 수 있습니다.  
세션에 기록된 변경이 하나도 없으면 버튼은 동작하지 않습니다.

Time Travel은 다이어그램의 읽기 전용 복사본을 별도로 열며, 다이어그램이 스크롤 위치와 확대/축소 레벨을 저장하는지와 상관없이 캔버스에 현재 보이는 스크롤 위치와 확대/축소 레벨로 보여 줍니다.  
슬라이더를 드래그하거나 트랙의 아무 곳이나 클릭해 편집 히스토리 전체를 이동하며 각 시점을 미리 볼 수 있습니다. 슬라이더의 가장 왼쪽은 첫 번째로 기록된 변경 직전 상태이며, 열릴 때는 현재 상태에 위치합니다.  
미리보기는 조작할 수 없습니다. 미니맵은 그려지지만 이동, 스크롤, 편집이 불가능하며 적용하기 전까지 실제 문서는 그대로 유지됩니다.

`Apply`를 누르면 선택한 시점으로 복원되고, `Cancel` 또는 `Esc`를 누르면 문서를 변경하지 않고 나갑니다.
