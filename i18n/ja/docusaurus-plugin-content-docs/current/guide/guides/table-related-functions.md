# テーブル関連機能

作成済みのテーブルとメモに対する操作（選択、移動、コピー、削除、色の指定、キャンバスに表示する内容の設定）と、その周辺のキャンバス操作をまとめています。  
前半はテーブルとメモの操作、続いてテーブルのプロパティ、テーブルへのフォーカス、インデックスと代替キー、自動レイアウト、データベースベンダー、最後にキャンバス自体のキャンバスツールバー、拡大・縮小、移動、Diff Viewer を扱います。  
テーブルをまとめる枠であるテーブルグループには、専用のページがあります。[テーブルグループ](./table-groups.md)を参照してください。

## 複数選択

次の 3 つの方法に対応しています。

- `Ctrl + drag` (Windows/Linux) or `⌘ + drag` (Mac)
- `Ctrl + click` (Windows/Linux) or `⌘ + click` (Mac)
- `Ctrl + A` or `Ctrl + Alt + A` (Windows/Linux)、`⌘ + A` or `⌘ + ⌥ + A` (Mac)

メモも同じ方法で選択でき、どちらの全選択ショートカットもすべてのテーブルとメモを一度に選択します。View Option → `Memos` で非表示にしたメモは、全選択にも選択範囲にも含まれません。[テーブルの表示オプション](#table-view-options)を参照してください。  
[テーブルグループ](./table-groups.md#グループの選択)は、タイトルバーを `Ctrl + click` (Windows/Linux) または `⌘ + click` (Mac) すると選択に加わりますが、全選択で選択されることはありません。  
`Ctrl + A` はキャレットに譲るため、セルの編集中はダイアグラムではなくテキストを選択します。  
テーブルやメモは、選択範囲が端に触れただけでは選択されず、中心を覆ったときに選択されます。テーブルグループは、選択範囲がグループの枠全体を囲んだときにだけ選択されるため、グループの内側に選択範囲を描くと、グループを含めずにテーブルだけを選択できます。  
すでに選択しているものを右クリックすると選択全体が維持されるため、`Color`、`Group selected tables`、`Delete selected` などのメニューの項目は選択全体に適用されます。それ以外のテーブル、メモ、テーブルグループを右クリックすると、`Ctrl` や `⌘` を押していてもそれだけが選択され、リレーションシップやキャンバスの空いている場所を右クリックすると選択が解除されます。  
`Escape` で選択を解除します。セルやメモ、テーブルグループ名の編集中、またはリレーションシップや `New Table Group` の作成中は、最初の `Escape` でそれを終了し、2 回目の `Escape` で選択を解除します。

![⌘ + drag と ⌘ + click でテーブルを選択し、⌘ + A ですべてのテーブルとメモを選択する様子](/img/demo-table-select.webp)

共同編集中は、各参加者の選択、フォーカスしているセル、選択範囲が参加者ごとの色でキャンバスに描画されます。[共同編集](../../api/advanced/collaborative-editing.md)を参照してください。

## 複数テーブルの移動

すでに選択に含まれているテーブルやメモをドラッグすると、修飾キーなしで選択全体が一緒に移動します。  
選択の外にある対象をドラッグすると、選択がその対象に置き換わり、それだけが移動します。`Ctrl + drag` (Windows/Linux) または `⌘ + drag` (Mac) では、どちらの場合も選択は維持されます。  
テーブルとメモを移動できるのはマウスの左ボタンだけです。右クリックはコンテキストメニューの対象を決めるだけで何も移動せず、中ボタンでドラッグすると、代わりにキャンバスの表示位置が移動します。[キャンバスの移動](#getting-around-the-canvas)を参照してください。

![選択した 2 つのテーブルの一方をドラッグすると両方が移動し、リレーションシップが追従する様子](/img/demo-table-multiple-move.webp)

選択している[テーブルグループ](./table-groups.md)も、そのテーブルを連れて移動します。選択していて、かつ移動するグループにも含まれるテーブルは、1 回だけ移動します。  
テーブルをドロップした位置によって、テーブルがグループに入ったりグループから出たりすることがあります。[テーブルの追加と削除](./table-groups.md#テーブルの追加と削除)を参照してください。

テーブルとメモは 1 つの重なり順を共有します。テーブルやメモを左ボタンまたは右ボタンで押すと、それがほかのすべてのテーブルとメモの前面に移ります。テーブルグループのタイトルバーを押すか、グループの本体を右クリックすると、そのグループのテーブルが前面に移ります。  
重なり順は保存されません。ダイアグラムを開き直すと、テーブルはファイルに記載されている順に重なり、メモはすべてテーブルより上に重なります。

## テーブルとメモのコピー / 貼り付け {#copyingpasting-tables-and-memos}

選択しているテーブルとメモをコピーし、新しいテーブルとメモとして貼り付けます。  
ショートカット: `Ctrl + C` (Windows/Linux) または `⌘ + C` (Mac)、`Ctrl + V` (Windows/Linux) または `⌘ + V` (Mac)

コピーしたテーブルは名前、コメント、カラム、色を保持し、コピーしたメモは本文、サイズ、色を保持します。  
インデックスとリレーションシップも一緒にコピーされます。インデックスはコピーしたテーブルへ丸ごとコピーされ、リレーションシップは両端のテーブルがどちらもコピー対象に含まれているときに、種類と、ON DELETE と ON UPDATE のアクションを保持したままコピーされます。片側だけのリレーションシップは、元のテーブルを指したまま残るのではなく破棄されます。  
貼り付けたコピーが新しい選択になり、同じコピーを繰り返し貼り付けると毎回 `50px` ずつずれるため、重なって積み上がることはありません。  
コピーは[テーブルグループ](./table-groups.md)を引き継ぎません。貼り付けたテーブルは、グループの枠の内側に置かれた場合でもどのグループにも属さず、選択しているグループはコピーされません。  
View Option → `Memos` でメモを非表示にしている間も、貼り付けるとコピーに含まれるメモは非表示かつ未選択の状態で追加されるため、新しい選択になるのは貼り付けたテーブルだけです。

![リレーションシップでつながる 2 つのテーブルをコピーし、リレーションシップごと 2 回貼り付ける様子](/img/demo-table-copy-paste.webp)

フォーカスしているテーブル内でカラムを選択している場合は、同じショートカットでそのカラムがコピーされます。[テーブルの編集](./table-editing.md)を参照してください。

## テーブルとメモの複製

`Alt` を押しながら、テーブルやメモをマウスの左ボタンでドラッグします。  
半透明のプレビューがポインタに追従し、ボタンを離すとプレビューの位置にコピーが配置されます。  
つかんだ対象がすでに選択に含まれている場合は、選択全体が複製されます。含まれていない場合は、ポインタの下の対象が新しい選択になります。  
動かさずに `Alt + click` すると、コピーは右下に `50px` ずれた位置に配置され、その位置がすでに埋まっている場合はさらにずれた位置に配置されます。

複製が引き継ぐ内容は貼り付けと同じで、名前、コメント、カラム、色、メモのサイズに加えて、コピー対象の中で完結するインデックスとリレーションシップも引き継ぎます。貼り付けと同じく、複製はどのテーブルグループにも属しません。  
テーブルグループのタイトルバーを `Alt + drag` すると、通常のドラッグと同じようにグループが移動します。グループが複製されることはありません。

![Alt + drag でテーブルを複製し、Alt + click で右下にもう 1 つコピーを置く様子](/img/demo-table-duplicate.webp)

## テーブルとメモの削除

選択しているテーブル、メモ、[テーブルグループ](./table-groups.md)を削除します。  
ショートカット:

- `Delete` または `Backspace`。選択全体を削除します。ただし、選択しているのがテーブル 1 つだけで、そのテーブルのカラムをいくつか選択していて、拡大・縮小のレベルが `70%` より大きい場合は、代わりにそのカラムを削除します。[カラムの削除](./table-editing.md#カラムの削除)を参照してください。
- `Ctrl + Backspace` または `Ctrl + Delete` (Windows/Linux)、`⌘ + Backspace` または `⌘ + Delete` (Mac)。カラムを選択している間でも、常に選択しているテーブル、メモ、テーブルグループを削除します。

![Delete キーでテーブルをリレーションシップごと削除し、続いてメモのメニューの Delete selected でテーブルとメモをまとめて削除する様子](/img/demo-table-remove.webp)

コンテキストメニューからも削除できます。テーブルやメモのメニューの最後の項目は、そのテーブルやメモが選択している 2 つ以上の対象の 1 つである間は `Delete selected` と表示され、選択全体を削除します。それ以外の場合は `Delete` と表示され、そのテーブルやメモだけを削除します。選択しているカラムの行の上では、テーブルのメニューの項目は代わりに `Delete column` または `Delete columns` と表示されます。[カラムの削除](./table-editing.md#カラムの削除)を参照してください。

テーブルを削除すると、そのリレーションシップとインデックスも一緒に削除されます。テーブルグループを削除しても、そのテーブルはどのグループにも属さない状態で残ります。[グループの削除](./table-groups.md#グループの削除)を参照してください。  
確認はなく、削除は 1 回ごとに Undo の 1 ステップになります。`readonly` のエディタでは何も削除されません。  
`Delete` と `Backspace` は、押し続けても削除は 1 回だけで、リレーションシップを削除することはありません。[リレーションシップの編集](./relationship-editing.md#削除)を参照してください。セル、メモ、そのほかのテキスト入力欄に入力している間は、代わりにテキストを編集します。  
設定では、この 2 つのキーは `Delete Selection` として表示されます。[ショートカット](./settings.md#ショートカット)を参照してください。

## テーブルとメモの色指定

カテゴリごとに区別できるよう、色を指定できます。  
テーブルは左端に沿って、メモは上部に沿って色が付きます。その左端または色帯を左ボタンでクリックするか、テーブルやメモのコンテキストメニューで `Color` を選ぶと、ポインタの位置にカラーピッカーが開きます。色はクリックしたものだけでなく、選択しているすべてのテーブル、メモ、テーブルグループに適用されます。  
テーブルグループの色は、グループ自体のメニューの `Color` で指定します。色の付いたグループに属するテーブルは、ヘッダー全体にグループの色が付き、左端には自身の色がそのまま残ります。[グループの色指定](./table-groups.md#グループの色指定)を参照してください。

![メモの色帯から Blue のプリセットを選んで、選択している 2 つのテーブルとメモに適用し、No color で色を外す様子](/img/demo-table-color.webp)

ピッカーには、上から順に次のものが並びます。

- 彩度と明度のエリア、続いて色相スライダーとその横の色のプレビュー。ブラウザがスポイトに対応している場合は、スライダーの前にあるスポイトのボタン `Pick a color from the screen` で、画面上のどこからでも色を取得できます。
- `Hex`、`R`、`G`、`B` の入力欄。`Hex` は、`#` の有無を問わず 3、4、6、8 桁の 16 進数、または貼り付けた `rgb()`、`hsl()`、CSS の色名を受け付けます。6 桁または 8 桁がそろった値は入力した時点で適用され、それ以外の値は `Enter` を押すか入力欄を離れたときに適用されます。`R`、`G`、`B` は整数を受け付け、`255` より大きい値は `255` として読み取り、`Enter` を押すか入力欄を離れたときに適用されます。ピッカーが読み取れないテキストは破棄されます。
- 2 行に 8 個ずつ並んだ 16 個のプリセットの色見本。Red、Orange、Amber、Yellow、Lime、Green、Teal、Cyan、Blue、Indigo、Violet、Purple、Pink、Crimson、Brown、Gray です。色見本にポインタを重ねると、その 16 進数のコードが表示されます。
- `Document colors`: ドキュメントのテーブル、メモ、テーブルグループですでに使われている色を、多く使われている順に最大 8 色表示します。該当する色がある場合にだけ、この行が表示されます。
- `No color`。

色は常に不透明です。ピッカーには透明度の設定がなく、入力または貼り付けた値に透明度が含まれていても破棄されます。  
ピッカーを開いただけでは何も変わらず、選択している対象にすでに付いている色を選んでも Undo のステップは追加されません。

`No color` は、選択しているすべてのテーブル、メモ、テーブルグループの色を Undo の 1 ステップで外し、ピッカーを閉じます。選択している対象のいずれかに色が付いている間は、テーブル、メモ、テーブルグループのコンテキストメニューで `Color` のすぐ下に `Remove color` が表示され、ピッカーを開かずに同じ操作を行います。

ピッカーは開くとキーボード入力を受け取り、`Tab` と `Shift + Tab` でピッカー内のコントロールの間を巡回します。矢印キーは、エリアと色相スライダーを 1 ずつ、`Shift` を押しながらでは 10 ずつ動かし、色見本の間では移動するたびにその色を適用します。  
ピッカーがキーボード入力を受け取っている間も、Undo と Redo、拡大・縮小のショートカット、クイック検索、検索と置換はエディタに届きますが、それ以外のエディタのショートカットは届きません。[削除](#テーブルとメモの削除)のショートカットでは何も削除されず、`Delete` と `Backspace` は `Hex`、`R`、`G`、`B` の入力欄のテキストを編集するだけです。  
`Escape` を押すか、ピッカーの外側のキャンバスを押すと、ピッカーが閉じます。

## テーブルの表示オプション {#table-view-options}

次の表示オプションを提供します。

- Table Comment
- Column Comment
- DataType
- Default
- Not Null
- Unique
- Alternate Key
- Auto Increment
- Relationship
- Referential Actions
- Table Groups
- Memos

`Unique`、`Alternate Key`、`Auto Increment` は既定でオフで、それ以外は既定でオンです。  
`Alternate Key` は、`AK1.1` のように各代替キーのカラムにマークを付けます。[代替キー](#alternate-keys)を参照してください。  
`Referential Actions` は、リレーションシップの ON DELETE と ON UPDATE のアクションによってコネクタの子側の端に付く `D:` と `U:` のラベルを表示します。[コネクタの読み方](./relationship-editing.md#reading-a-connector)を参照してください。オフにして非表示になるのはそのラベルだけで、テーブルやコネクタは動きません。  
`Table Groups` は、[テーブルグループ](./table-groups.md)と、そのテーブルのヘッダーに付くグループの色を表示します。オフにすると、キャンバス、ミニマップ、画像の書き出しでそれらが非表示になりますが、テーブルは動かず、すべてのテーブルは自身のグループに属したままです。[グループの非表示](./table-groups.md#グループの非表示)を参照してください。  
`Memos` はメモを表示します。オフにすると、キャンバス、ミニマップ、画像の書き出しですべてのメモが非表示になり、テーブルやコネクタは動きません。非表示のメモは場所を取らないため、スクロールバー、ミニマップ、`Go to content` コンパスの対象から外れます。  
メモを非表示にすると、メモの選択が解除され、開いているメモの編集も終了します。[検索と置換](./find-and-replace.md)とクイック検索の `:` は、非表示のメモを検索しません。非表示の間は、コンテキストメニュー、クイック検索、[ウェルカム画面](./editing-start.md#ウェルカム画面)から `New Memo` がなくなり、`Alt + M` でもメモは追加されません。貼り付けと [Import and Add](./file-import-export.md#import-and-add) では、含まれるメモが引き続き非表示かつ未選択の状態で追加されます。  
`readonly` のエディタでは、切り替えても何も変わりません。

![View Option の項目を切り替えてテーブルの表示が変わり、Alternate Key で複合ユニークインデックスに AK1.1 と AK1.2 のマークを付け、続いて Memos をオフにしてからオンに戻す様子](/img/demo-view-options.webp)

Visualization タブの `Flow` モードのカードは、これらのオプションに従いません。カードは独自の[行の表示](./visualization.md#row-display)を使い、`Relationship` がオフでもコネクタを描画します。

## テーブルのプロパティ {#table-properties}

テーブルのプロパティパネルを開きます。  
テーブルのコンテキストメニューで `Table Properties` を選ぶと、右クリックしたテーブルのパネルが開きます。テーブルを選択して `Alt + Space` を押しても開けます。  
パネルは暗くなったキャンバスの中央に開き、開くと、開いている[検索と置換](./find-and-replace.md)のパネルは閉じます。ヘッダーには `Table Properties` のタイトル、最近開いた 5 つのテーブルのチップ（現在のテーブルはハイライトされます）、閉じるボタンが並びます。チップをクリックすると、パネルを開き直さずにそのテーブルへ移動します。  
ヘッダーの下には `Indexes`、`Schema SQL`、`Code Generator` の 3 つのタブがあります。パネルの大きさは 3 つのタブで共通のため、タブを切り替えてもパネルが動いたり大きさが変わったりすることはありません。  
閉じるボタン、`Escape`、またはパネルの外側のクリックで閉じます。

`Indexes` タブについては[インデックス](#indexes)を参照してください。  
`Schema SQL` タブには、選択している[データベース](#databases)向けのテーブルの DDL が表示されます。`CREATE TABLE`、一部のデータベースが Unique のカラムに対して別途書き出す制約、そしてインデックスです。ツールバーの [Schema SQL](./schema-sql.md) タブの設定にかかわらず、常にヘッダーも前後のスクリプトもない通常の `CREATE` 文を書き出します。オプションパネルはなく、コンテキストメニューには `Database` と `Bracket` しかありません。  
`Code Generator` タブは、このテーブルだけのコードを生成します。[コード生成](./code-generator.md)を参照してください。

`readonly` のエディタでもパネルは開き、タイトルの横に `Read only` のバッジが表示されますが、`Indexes` タブでは何も編集できません。

## テーブルへのフォーカス {#focusing-on-tables}

Visualization タブを `Flow` モードで開き、選んだテーブルと、そこからリレーションシップ 1 つでつながるすべてのテーブルに絞り込んで表示します。  
テーブルのコンテキストメニューの `Focus on this table` から開くか、1 つ以上のテーブルを選択して `Alt + F` を押します。  
右クリックしたテーブルが複数選択しているテーブルの 1 つである場合、項目は `Focus on selected tables` と表示され、選択全体にフォーカスします。選択の外にあるテーブルを右クリックした場合は、そのテーブルだけにフォーカスします。  
ショートカットは選択しているテーブルを対象とし、メモは除外します。テーブルを選択していない場合は何もしません。  
選択している[テーブルグループ](./table-groups.md)は、ショートカットでもメニューの項目でも対象になりません。グループのテーブルが対象になるのはテーブル自体を選択している場合だけで、グループのメニューの `Select tables` を使うとそのように選択できます。  
絞り込んだビューの表示内容と、ダイアグラム全体に戻る方法については、[可視化](./visualization.md#focusing-on-tables)を参照してください。

## インデックス {#indexes}

インデックスはテーブルのプロパティパネルの `Indexes` タブで定義し、書き出す Schema SQL に含まれます。

左側には、テーブルのキーとインデックスが 2 つのグループに分かれて一覧表示されます。  
`Keys` はテーブルにキーがある場合に表示され、カラムが宣言しているキーを一覧表示します。まず PK が付いたカラムに対する `PK_<テーブル名>`、続いて Unique が付いたカラムごとの `UQ_<テーブル名>_<カラム名>` がカラム順に並びます。名前は選択しているデータベースの Schema SQL に従うため、`Bracket` が `None` のとき、`sales.users` のようなスキーマ修飾されたテーブルでは、Databricks と Snowflake 以外のすべてのデータベースで `PK_users` と表示されます。[スキーマ修飾されたテーブル名](./schema-sql.md#スキーマ修飾されたテーブル名)を参照してください。それぞれに `PK` または `UQ` のタグとロックのアイコンが付きます。ここでは読み取り専用で、カラムの [PK](./table-editing.md#カラムの主キー) と [Unique](./table-editing.md#not-null-unique-auto-increment) のフラグによってのみ変わります。  
`Indexes` には、テーブルのインデックスが追加した順に一覧表示されます。各インデックスには、ユニークにする `UQ` トグル、名前の入力欄、削除する `x` があります。[代替キー](#alternate-keys)であるインデックスには、`AK1` のようにその番号も表示されます。インデックスは一覧の下部にある `Add Index` で追加します。

右側には、テーブルのカラムが `Columns` の下にチェックボックス付きで一覧表示されます。左側でインデックスを選択するまでは編集できません。  
カラムをチェックすると選択中のインデックスに追加され、チェックを外すと削除されます。キーを選択すると、そのカラムにチェックが付いた状態で表示されますが、チェックボックスは無効のままです。  
選択中のインデックスのカラムは、下部の `Index order` に一覧表示されます。グリップハンドルでドラッグすると並べ替えられ、行の `ASC` または `DESC` をクリックすると並び順が切り替わります。代替キーでは、各行の末尾にその `AK<n>.<m>` のマークが付きます。一覧には一度に 3 行が表示され、残りはスクロールして表示します。

`readonly` のエディタでは、キーやインデックスを選択するとそのカラムは表示されますが、`Add Index` と `x` はなく、タブ内のほかの項目も変更できません。

![orders でテーブルのプロパティを開き、Indexes タブでインデックスの上に PK と UQ のキーが並ぶのを確認してから、member_id と ordered_at DESC のインデックスを追加し、Schema SQL タブで確認する様子](/img/demo-table-properties.webp)

## 代替キー {#alternate-keys}

代替キーとは、2 つ以上のカラムにまたがるユニークインデックスです。つまり、`Indexes` タブで `UQ` トグルがオンになっていて、テーブルのカラムが 2 つ以上チェックされているインデックスです。  
1 つのカラムだけのユニークインデックスは、そのカラムの Unique フラグ以上のことを表さないため代替キーではありません。通常のインデックス、主キー、Unique が付いたカラムも代替キーではありません。

[表示オプション](#table-view-options)で `Alternate Key` をオンにすると、ダイアグラムは各代替キーのカラムに、erwin や IDEF1X と同じ書き方で `AK1.1`、`AK1.2` などのマークを付けます。このオプションは既定でオフです。

キーの番号は、インデックスを追加した順ではなく、そのカラムがテーブルのどこにあるかで決まります。`Index order` の先頭のカラムがテーブルの最も上にあるキーが `AK1` です。先頭のカラムが同じ場合は各キーの次のカラムで決まり、より長いキーの先頭部分にあたるキーは、その長いキーより前になります。  
テーブル内でカラムを移動したり、キーの `Index order` を並べ替えたりすると、キーの番号が変わることがあります。キーの削除を Undo するとキーには元の番号が戻り、すべての共同編集者に同じ番号が表示されます。

キーの各カラムには `AK<n>.<m>` のマークが付きます。`n` はキーの番号、`m` はキーの `Index order` におけるそのカラムの位置です。複数のキーに含まれるカラムには、すべてのマークがカンマでつながれて付きます。  
例えば、`a`、`b`、`c` のカラムを持つテーブルで (`c`, `a`) と (`b`, `a`) のユニークインデックスがある場合、`b` が `c` より上にあるため、`AK1` = (`b`, `a`)、`AK2` = (`c`, `a`) になります。そのため、`b` は `AK1.1`、`c` は `AK2.1`、`a` は `AK1.2,AK2.2` と表示されます。

マークは行の最後、[カラム順](./settings.md#adjusting-column-order)で最後になるセルのさらに後ろに描画されます。セルではないため、フォーカス、編集、コピーの対象になることはありません。[テーブルの編集](./table-editing.md)を参照してください。  
マークは何も置き換えないため、主キーや外部キーのカラムにも AK のマークが付きます。行の先頭のキーのアイコンは引き続き PK と FK を示し、Unique のセルにもそれ自体の `UQ` がそのまま表示されます。  
代替キーを持つテーブルは、すべての行の最後のセルの後ろに、最も長いマークが収まる余白を確保します。代替キーを持たないテーブルの幅は変わりません。  
マークは ERD キャンバスに表示されますが、`70%` 以下でテーブルが名前だけの表示に折りたたまれているときは表示されません。[画像の書き出し](./file-import-export.md#画像)にも表示され、画像では拡大・縮小のレベルにかかわらず、すべてのテーブルが省略なしで描画されます。Visualization タブの `Graph` モードの[ホバープレビュー](./visualization.md#hover-preview)にも表示されますが、`Flow` のカードには表示されません。

`Indexes` タブには、このオプションがオンかどうかにかかわらず番号が表示されます。[インデックス](#indexes)を参照してください。

## 自動レイアウト {#auto-layout}

すべてのテーブルをキャンバス上に配置します。  
キャンバスのコンテキストメニューまたはクイック検索から `Auto Layout` を開き、4 つのレイアウトから 1 つを選びます。

| レイアウト | 何を描くか |
| --- | --- |
| `Force` | シミュレーションです。リレーションシップがテーブルを引き寄せ、隣り合うテーブルは互いに押し離し、重なったテーブルは離れます。 |
| `Flow` | リレーションシップに沿って左から右へ流れます。コネクタごとにテーブルへ接する位置を分けます。線の交差を少なくしようとしますが、ほかのレイアウトなら避けられる交差が残ることもあります。 |
| `Tree - vertical` | 上から下へ階層に並べます。親テーブルが、それを指す外部キーを持つテーブルの上に置かれます。 |
| `Tree - horizontal` | 同じ階層構造を、左から右へ並べます。 |

`Force` は配置が落ち着くまでプレビューを開き、表示される通知に `Apply` と `Cancel` があります。  
プレビューの表示範囲は配置を始めた時点のダイアグラムに合わせられるため、配置が落ち着くまでの間にテーブルが枠の外へ出ることがあります。プレビューは `70%` 以下で描画されるため、テーブルは名前と色の付いた端だけの表示になります。  
`Apply` を押すと、その時点の位置で確定します。押さない場合も、静止した時点で配置は自動的に適用されます。`Cancel` または `Escape` ではダイアグラムは元のままです。

残りの 3 つはメインスレッドの外で一度に計算されるため、見守るものはありません。計算の間は通知が表示され、できあがった配置はダイアグラムがすでに占めている範囲の中央に置かれます。`Cancel` または `Escape` は、もう待っていないレイアウトを破棄します。Shared Worker を動かさないホストでは `Could not place tables` で終わります。[Web Worker](../../api/installation.md#web-workers) を参照してください。60 秒以内に結果が返ってこないレイアウトも、同じように終わります。

どれを選んでも動くのはテーブルとテーブルグループで、メモはその場に残ります。自分自身を指すリレーションシップは無視し、同じ 2 つのテーブルの間に複数あっても 1 つとして数えます。  
どのレイアウトも、グループが表示されているかどうかにかかわらず各グループのテーブルをまとめたまま配置し、テーブルを含む各グループの枠をそのテーブルに合わせます。[テーブルグループ](./table-groups.md#自動レイアウト)を参照してください。  
結果は 1 件の履歴として記録されるため、1 回の Undo ですべてのテーブルとグループが元の位置に戻ります。

![散らばったテーブルを、キャンバスのコンテキストメニューの Flow 自動レイアウトで整え、リレーションシップに沿って左から右へ並べる様子](/img/demo-automatic-table-placement.webp)

## データベース {#databases}

対応しているデータベースは次のとおりです。

- Databricks
- MSSQL
- MariaDB
- MySQL
- Oracle
- PostgreSQL
- Snowflake
- SQLite

データベースは、キャンバスのコンテキストメニュー、Schema SQL タブと Code Generator タブのオプションパネルまたはコンテキストメニュー、クイック検索の `Database` から選びます。どこで選んでも同じ設定が変わります。

この設定は、書き出す Schema SQL の構文、DataType の自動補完、生成されるコードや読み込んだスキーマで解決される型を決定します。  
[Schema SQL](./schema-sql.md#オプションパネル) タブで書き出せる `Statements` と `Header` の選択肢も、この設定で決まります。データベースにない選択肢はオプションパネルに淡い色で残り、SQL はそのデータベースにある最も近い選択肢で書き出されます。  
また、Schema SQL とコード生成の ORM の対象がどの ON DELETE と ON UPDATE のアクションを書き出すか、リレーションシップのメニューでどのアクションに `not in <database>` の注記が付くかも決定します。[ON DELETE と ON UPDATE](./relationship-editing.md#on-delete-and-on-update) と[コード生成](./code-generator.md#database)を参照してください。  
Schema SQL の読み込みでは、`TIMESTAMP WITH TIME ZONE`、`public.mood`、`integer[]` のように、エディタの一覧にあるかどうかにかかわらず、カラムのデータ型が引数リストを含めてそのまま保持されます。[データ型](./file-import-export.md#data-types)を参照してください。DataType の自動補完が候補に出すのは、選択しているデータベースの一覧にある型だけです。

## キャンバスツールバー {#canvas-toolbar}

キャンバスの下端の中央には小さなツールバーが浮いていて、キャンバス自体に対する道具がまとまっています。

- ハンドとポインタ。既定はポインタで、ハンドにすると空いている場所だけでなくテーブルの上でもドラッグが表示位置の移動になります。`Space` で切り替えます。[`New Table Group`](./table-groups.md#グループの描画) の枠を描いている間はどちらも選択された状態にならず、どちらかをクリックするか、`Space` を押すか、リレーションシップの記法を選ぶと、グループを追加せずに描画を終了します。
- 拡大・縮小。`Zoom out`、パーセントで示した現在の拡大・縮小のレベル、`Zoom in` が並びます。2 つのボタンは、拡大・縮小のショートカットと同じように段階的に拡大・縮小し、パーセント表示をクリックすると `100%` に戻ります。
- 4 種類のリレーションシップ記法。リレーションシップを開始するときのものと同じです。[編集を始める](./editing-start.md)を参照してください。リレーションシップはテーブルを 2 つクリックして描くため、記法を選ぶと道具はポインタに戻ります。
- Zen モード `Alt + Z`。キャンバスとこのツールバーだけを残して、ほかをすべて隠します。もう一度 `Alt + Z` を押すか、ボタンを押すと元に戻ります。開いている[検索と置換](./find-and-replace.md)のパネルは隠れずに残り、上部のツールバーが空けた場所へ上に移動します。
- `Go to content` コンパス。テーブルも、表示されているメモやテーブルグループも画面にない間だけ、ツールバーの末尾に加わります。[キャンバスの移動](#getting-around-the-canvas)を参照してください。

ショートカットのあるボタンは、ツールチップにそのショートカットを表示します。  
`Force` の自動レイアウトのプレビュー、テーブルのプロパティ、Time Travel、Diff Viewer のいずれかが開いている間はツールバーが退き、閉じると再び表示されます。

![ハンドでテーブルの上から表示位置を移動し、Space でポインタに戻して、拡大・縮小を段階的に行い、⌥ + Z とボタンで Zen モードを切り替える様子](/img/demo-canvas-toolbar.webp)

## 拡大・縮小

`Ctrl + Wheel` (Windows/Linux) または `⌘ + Wheel` (Mac) で拡大・縮小します。ホイールだけを回すとキャンバスの表示位置が移動します。  
トラックパッドのピンチでも、ピンチした位置を中心に拡大・縮小します。タッチスクリーンでは 2 本の指でも拡大・縮小でき、指を動かすと表示位置も移動します。  
ショートカット: `Ctrl + Plus` (Windows/Linux) または `⌘ + Plus` (Mac)、`Ctrl + Minus` (Windows/Linux) または `⌘ + Minus` (Mac)  
`Ctrl + 0` (Windows/Linux) または `⌘ + 0` (Mac) は、画面の中心を保ったまま `100%` に戻します。

[キャンバスツールバー](#canvas-toolbar)の `Zoom out` と `Zoom in` のボタンは、`Minus` と `Plus` のショートカットと同じように拡大・縮小します。1 回押すごとに、画面の中心を保ったまま 4 パーセントポイントずつ変わります。2 つのボタンの間のパーセント表示は現在の拡大・縮小のレベルを示し、クリックすると `Ctrl + 0` (Windows/Linux) または `⌘ + 0` (Mac) と同じように `100%` に直接戻ります。

拡大・縮小のレベルは `10%` から `150%` までです。  
`70%` 以下ではテーブルが名前と色の付いた端だけの表示になり、拡大するまではセルの編集、セルのショートカット、コピーと貼り付けは動作しません。

同じ 3 つのショートカットは Visualization タブでも、`Graph` モードと `Flow` モードのどちらでも、それぞれのモードの範囲内で拡大・縮小します。[可視化](./visualization.md#toolbar)を参照してください。

![⌘ + Wheel でテーブルが名前だけの表示になるまで縮小し、⌘ + Plus、⌘ + Minus、⌘ + 0 で元に戻す様子](/img/demo-zoom.webp)

## キャンバスの移動 {#getting-around-the-canvas}

キャンバスに端はなく、設定するサイズもありません。テーブルとメモは置いた場所にそのままあり、以下のものはすべて固定の紙面ではなくダイアグラム自体を基準にしています。

キャンバスの空いている場所をドラッグすると表示位置が移動します。`Space` でハンドツールに切り替えれば、テーブルの上を含めてどこからでもドラッグできます。ホイールでも移動でき、`Shift + Wheel` は左右に移動します。  
[テーブルグループ](./table-groups.md#グループの選択)の本体、つまりタイトルバーの下の領域は、左ボタンに対してはキャンバスの空いている場所として扱われます。ドラッグすると表示位置が移動し、`Ctrl + drag` (Windows/Linux) または `⌘ + drag` (Mac) で選択範囲を描き、クリックすると選択が解除されます。  
移動できる範囲に制限はありません。ホイール、ドラッグ、ハンドツールのいずれでも、動かした分だけ表示位置が移動し、どの方向でもテーブルの先まで進みます。

マウスの中ボタン（ホイールを押し込む）でドラッグすると、ポインタでもハンドでも、キャンバスのどこからでも表示位置を移動できます。押した位置がテーブル、メモ、セル、アイコン、リレーションシップの上でも動作します。  
中ボタンでのドラッグは何も選択、移動、クリックせず、選択もそのまま維持されます。開いているコンテキストメニューとカラーピッカーは閉じ、ブラウザ自体の中クリックによるスクロールや貼り付けは始まりません。  
スクロールバー、ミニマップ、キャンバスツールバー、または編集中のセルやメモの上で中ボタンを押しても、表示位置は移動しません。

右上のミニマップは、ダイアグラムの四方に画面 1 つ分の余地、つまりスクロールバーが届く範囲を加え、粗いグリッドに合わせて外側へ広げた範囲を表示するため、縮小するほどミニマップの中のダイアグラムは小さくなります。クリックするとその位置へ表示が移動し、表示範囲の枠をドラッグすると表示位置が移動します。縮小するほど、表示範囲の枠はミニマップのより広い部分を覆うように大きくなります。  
ミニマップは各テーブルをそのテーブルの色で描き、表示されている各テーブルグループを、そのテーブルの後ろにグループの色の枠として描きます。  
右端と下端のスクロールバーも同じ範囲を表します。この範囲はダイアグラムが画面の片側のすぐ外にある位置から反対側のすぐ外にある位置までなので、描画されているダイアグラムより少なくとも画面 1 つ分長く、表示位置がダイアグラムの先にある間はさらに長くなります。Zen モード以外では、テーブル、表示されているメモ、表示されているテーブルグループが 1 つでもあれば、すべてが画面に収まっていても両方のスクロールバーが表示されます。メモしかなく、そのメモが View Option → `Memos` で非表示になっているドキュメントのように、これらが 1 つもない場合は、スクロールバーもミニマップも表示されません。  
スクロールバーのつまみやミニマップの表示範囲の枠をドラッグする移動だけは、止まる位置があります。テーブルが画面のすぐ外に出る位置までしか進まず、ドラッグを始めた位置がそれより外側だった場合は、その位置までしか進みません。

移動した結果、テーブルも、表示されているメモやテーブルグループも画面に残らなくなると、[キャンバスツールバー](#canvas-toolbar)の末尾に `Go to content` コンパスが加わり、最も近い対象を指す矢印とその距離を表示します。クリックすると、拡大・縮小のレベルを変えずにその対象が画面の中央に来ます。

![キャンバスの空いている場所のドラッグ、テーブルの上での中ボタンのドラッグ、ミニマップ、ホイールで表示位置を移動し、Go to content コンパスで戻る様子](/img/demo-canvas-navigation.webp)

## Diff Viewer

以前に保存したドキュメントと現在のドキュメントを比較できます。  
キャンバスのコンテキストメニューから `Diff Viewer` を選び、以前に書き出した `.json` のドキュメントを選択します。

ビューはキャンバスの上に開き、左に変更点、その隣に保存したドキュメントと現在のドキュメントが並びます。  
テーブルとカラムは名前で対応付けられます。2 つのドキュメントで値が異なるセルは両側で色が付き、保存したドキュメントでは赤、現在のドキュメントでは緑になるため、片側にしかないテーブルやカラムは全体に色が付きます。  
メモとテーブルグループは、それぞれの側にそのドキュメントのとおりに描画されますが、比較の対象にはなりません。色が付くことはなく、左の一覧にはテーブルとカラムしか表示されません。  
どちらの側も、ホイール、空いている場所やテーブルグループの本体のドラッグ、またはその側の上のどこでも中ボタンでドラッグすると表示位置が移動し、`Ctrl + Wheel` (Windows/Linux)、`⌘ + Wheel` (Mac)、またはピンチで拡大・縮小します。`70%` 以下ではキャンバスと同じようにテーブルが折りたたまれ、色付けは表示されません。  
両側とも読み取り専用のため、ドキュメントが変更されることはありません。ビューは、開くときに表示される `Diff Viewer` の通知の `Close` ボタン、または `Escape` で閉じます。
