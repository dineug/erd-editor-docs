**Generated:** 2026-11-03 · **Updated:** 2026-11-03

## Purpose

The Docusaurus 3 site published at <https://docs.erd-editor.io>. It documents
[erd-editor](https://github.com/dineug/erd-editor): the editor UI (Guide), the
`<erd-editor>`/`<erd-viewer>` custom elements and their companion packages (API), and the
`@dineug/erd-editor-mcp` server (MCP). English under `docs/` is the source. Each of the other
24 locales in `locales.mjs` is a full translation under `i18n/`. The animated WebP demos in
`static/img/` are recorded from the real editor by `scripts/demos/`.

`README.md` covers setup, the build, the project layout, the translation rules and the
per-locale search tokenizers. This file adds what an agent needs on top of it.

## For AI Agents

### Working In This Directory

- **The docs describe the code, so check the code first.** The erd-editor monorepo is checked
  out next to this repo at `../erd-editor` (packages such as `erd-editor`, `erd-editor-schema`,
  `erd-editor-yjs`, `mcp-server`, `vscode-extension`, `intellij-plugin`, `obsidian-plugin`).
  Check every behavior, option name, default, shortcut and UI label you write against that
  source at the documented version (its tags are `vX.Y.Z`). The history is full of
  corrections where a page promised more than the editor does.
- **Every English change is a 25-locale change.** If you edit a page under `docs/`, make the
  same change in all 24 `i18n/<locale>/docusaurus-plugin-content-docs/current/` copies before
  the work is done, or say plainly which locales are left. The rules are in `i18n/AGENTS.md`.
- **Version pins move together.** A release update bumps every pinned
  `@dineug/erd-editor@X.Y.Z` URL in English and in all 24 translations, so search for the old
  pin across `docs/` and `i18n/`, not only on the page you are editing. Notes that say which
  release introduced something keep their version.
- **Never put an `AGENTS.md` in `static/` or `src/pages/`.** `static/` is copied to the site
  as is, and the pages plugin turns any `.md` under `src/pages/` into a route. Under `docs/`
  it is safe only because of the `exclude` entry in `docusaurus.config.ts`. Keep that entry.
- **Don't run `pnpm deploy`.** It pushes to the `gh-pages` branch of `dineug/erd-editor`,
  which is not where this site is hosted (README, Deployment).
- **Commits:** Conventional Commits, enforced by the hook. Release updates use
  `feat: bring the docs up to date with erd-editor X.Y.Z`. Corrections use `docs: …` or
  `fix: …`, and housekeeping uses `chore: …`. A body lists what is new and what was corrected.

### Testing Requirements

- `onBrokenLinks: 'throw'`: a link to a missing route fails the build. So does a Markdown
  file link that doesn't resolve: `onBrokenMarkdownLinks: 'warn'` prints a warning, but the
  link keeps its `.md` URL, and the route check then fails it. A broken anchor
  (`onBrokenAnchors`, default `warn`) only prints `Docusaurus found broken anchors!`, so grep
  the build output for that line and for `[WARNING]`.
- After content changes, build the locales you touched: `pnpm build en ko ja` (any subset;
  `en` always runs first because its build empties `build/`). A full `pnpm build` is 25
  sequential builds, so run it in the background.
- `pnpm typecheck` after changes to `src/`, `docusaurus.config.ts` or `sidebars.ts`.
- Search exists only in a production build (`pnpm build && pnpm serve`), not in `pnpm dev`.
- After a translation pass, compare the structure of each translated page with English:
  headings, images, code blocks, tables and list items. Code blocks must be byte-equal.

### Common Patterns

- Page front matter has `sidebar_position` and a one-sentence `description`. The H1 is the
  page title.
- Prose often puts one sentence per line and joins them with Markdown hard breaks (two
  trailing spaces). Don't strip trailing whitespace from `.md` files.
- Internal links are relative file links (`../api/installation.md`,
  `./guides/embedding.md#anchor`). Images are absolute site paths (`/img/demo-*.webp`) with
  alt text that narrates the clip step by step.
- Keyboard shortcuts are written the way the editor shows them (`⌘ + ⌥ + 4`, `Alt + M`).
